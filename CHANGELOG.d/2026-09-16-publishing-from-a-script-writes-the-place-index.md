---
date: 2026-09-16
title: "Publishing from a script now writes the place-name index, so the first customer's maps are searchable by the villages on them"
---

- **`scripts/publish-baseline.mjs` and `scripts/seed-demo.mjs` write the place-name sidecar when they move the published pointer.** Until today `writePlacesSidecar()` was called from exactly one production path — the approve handler in `src/routes/review.js` — and a map published from the command line got no sidecar at all. That is how the first real customer's four St Neots maps went out on 15 September. Read off the live site on 16 September, before the fix: searching **Tilbrook** or **Abbotsley** returned *no map published through this portal covers it*, although the published sheet's routes 150, 18 and C2 all call there, and **Boxworth** returned St Ives rather than St Neots. All four maps answered to their own titles and to nothing else, which is why the search looked as though it worked.

- **Nothing went red, and nothing could have.** `buildIndex()` skips a version with no sidecar in one line, under a comment written for the one-off P9 backfill — so a permanent defect wore the clothes of a temporary one. `scripts/test-search.mjs` could not see it either: its own `seedMap()` helper calls `writePlacesSidecar` itself, "mirroring what the approve handler does", so the suite proved that a sidecar makes a map searchable while nothing proved that publishing wrote one.

- **`scripts/check-publish-paths.mjs` records the requirement as a rule about the class rather than as a line in one handler.** Every call site that moves the published pointer is declared, with what it does and whether it writes a sidecar; an undeclared site is a finding, a declaration with no code behind it is a finding, and a disagreement is a finding in both directions — a site declared as writing that has stopped (this morning's state) and a site declared exempt that has quietly started. Declared rather than inferred, because the revert path is the proof that inferring would be wrong: it moves the pointer and must **not** write one, since the version reverted to has its own sidecar from the day it was published. It runs as a preflight in `npm test`.

- **`scripts/prove-red-publish-paths.mjs` breaks it eight ways**, each against its own throwaway copy of `src/` and `scripts/` so nothing is left mutated in a checkout other sessions share. Arm 1 is the exact state `main` was in this morning. Arm 8 pushes the sidecar write sixty lines down the same file and proves the search window is load-bearing rather than wide enough to answer for any call anywhere. Two controls: the real tree is clean, and a new `test-*.mjs` that publishes is skipped **and says it was skipped**.

- **`scripts/test-publish-baseline-search.mjs` spawns the real script** and asks the reader's question — type the name of a village on the sheet, is the map there? It seeds a draft, checks the map is *not* findable first, runs `publish-baseline.mjs` as an operator would, and then searches from a fresh process. Watched go red against the unfixed script: five checks, including the search itself.

- **A running portal does not see new place names until it is restarted, and the script now says so.** The sidecars are on disk and permanent, but `src/search/index.js` caches the built index in process against a counter only that process can bump, so `bumpSearchIndex()` in a command-line script would move a counter in a process about to exit. The same is true of `npm run places:build`, which is what back-fills the four maps already published.
