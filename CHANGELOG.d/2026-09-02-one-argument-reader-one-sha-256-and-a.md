date: 2026-09-02
title: "One argument reader, one SHA-256, and a path you can import without opening a database"
---
- **`scripts/lib/cli.mjs` is the one argument reader.** Thirteen scripts each carried their own three-line `arg`/`has`, in four spellings — some over `process.argv`, some over `process.argv.slice(2)`, one returning `null` where the rest returned `undefined`, and one guarding against the next token being another flag while the rest did not. Each copy was trivial; the cost was that the guard existed in one of them.
- **A flag's value may no longer begin with `--`, and that is a change to what every caller does.** The majority body read the next token whatever it was, so `--note --quiet` set the note to the string `"--quiet"` **and** lost `--quiet`, silently, on scripts that write to the VPS. The shared reader takes the stricter rule one of the thirteen already had, which is also the rule the engine's `assets/cli.js` uses, so the two repositories now agree about what a flag is. `argAllowingDashes` is there for a value that legitimately looks like one; nothing here passes one.
- **`confirm('local' | 'remote')` is the "really do it" vocabulary as a function**, so a script cannot invent a fifth spelling of it: local mutators report by default and write on `--apply`; anything reaching the VPS does it by default, with `--dry-run` to see the plan and `--yes` to confirm.
- **`src/db/paths.js` exports `DATA_DIR`, `DB_PATH` and `MAPS_DIR` and imports nothing but `node:path` and `node:url`.** Importing `src/db/index.js` opens the SQLite file, applies `schema.sql` and runs every migration — and `fix-badge-contrast.mjs`, `rerasterize-stored.mjs` and `restamp-renders.mjs` were doing all of that as a side effect of wanting to know where `data/maps` is, without ever touching `db`. Two more scripts had already noticed and worked around it by re-deriving the path, each with its own copy and a comment saying why, which is how a fourth spelling was one script away.
- **`src/hash.js` is the one SHA-256.** Two of the ten sites were the same security primitive under two names — `sessionTokenHash` in `src/auth/index.js` and `tokenHash` in `src/db/index.js`, plus a third written inline in the migration that hashes stored tokens. They agreed, which is the only reason sessions worked: a token is hashed on the way in by one and looked up by the other, so the day the two spellings differ every session in the database stops resolving and nothing in the code says why. The two audit tests still compute the hash themselves, deliberately — an independent computation in a test is the control, and a test using the function under test can only tell you it is deterministic.
- **`vendor-engine.mjs --add <engine/path.js> --source <skill/path.js>`** closes the gap the July 2026 engine-deduplication proposal left. `UNRESOLVED` used to end with "add its manifest row by hand", and the row holds a SHA-256, which is the one thing in this repository nobody can check by eye. `check-vendored.mjs` now prints the exact `--add` command for the file it could not resolve; the row's hash is written by `restampManifest()` from the bytes that landed rather than typed. Where the skill trees are present the source is resolved by looking; where they are not, the likely paths are offered and marked unverified, because a guess printed as a fact is how a wrong `source` gets committed and a wrong `source` makes `DRIFTED` mean nothing for that row for ever.
- **`skillRootDefault` is out of `engine/vendored.json` and into `SKILL_ROOT` in `.env`**, documented in `.env.example`. It was one laptop's absolute path, tracked into a repository that also runs on a VPS and in CI. `npm run check:vendored` and `npm run vendor:engine` now load `.env`, without which moving the value would have quietly switched the source half of the drift check off on the only machine that can run it.
- **Proved able to fail.** `scripts/test-portal-lib.mjs` (32 assertions) and `scripts/prove-red-portal-lib.mjs` (seven mutations plus a control, each required to redden *the assertion that names it*). Two of the seven earned their place: replacing `--add`'s `PENDING` placeholder with a literal hash **survived**, and the survivor was right — `restampManifest()` rewrites every row anyway, so the placeholder is not load-bearing and the real property is that the restamp runs at all; and the numeric-token case first went red on a stack trace rather than on its own line, because `createHash().update(123)` throws and a suite that dies reports nothing.
- **One pre-existing table has rendered wrong since it was written.** `docs/_archive/GO-LIVE.md`'s host-setup checklist declares two columns and every one of its nine rows has three, so the third cell has been dropped by every markdown renderer that has ever shown it. Found by pointing `buses-data`'s `check-tables.mjs` at `docs/`, which nothing has ever done — the portal is the one repository of the three whose documents no checker reads.
