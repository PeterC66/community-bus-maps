title: "Five things a reader found in the /maps search: a shared link that explained nothing, a link that stole the tab, and three doors marked \"organisation\""
---

- **A `?q=` link now says what the search did.** The sentence above the grid lived in `public/js/public-maps.js` and nowhere else, and that file does no first render — so `https://busmaps.uk/maps?q=Eynesbury` arrived with `#searchMeta` still `hidden` and empty. A reader who followed that link got a **Buckinghamshire** map for a **Cambridgeshire** village with nothing on the page to say the spelling had been read as "Aylesbury"; typing the query into the box instead showed the correction, which is worse than never showing it. The server read `q`, called `searchPlaces()` and threw `corrected` away. The sentence is now `searchMeta()` in the shared card module, rendered by the server and by the browser from one string — the same argument that module's own header makes about the grid, finally applied to the line above it. Driven on a real server: `/maps?q=Eynesbury` returns *No exact match for “Eynesbury” — showing results for “Aylesbury”.*

- **Links that leave this site open in a new tab, and say so.** `Open their map page`, `Their bus pages` and the `But: <authority> publishes one for …` links all carried `rel="nofollow noopener"` and no `target`. Each goes to a council website where the reader typically has several more clicks before reaching a map, so they came back, if at all, by pressing Back through a site they had been navigating. Each now carries `target="_blank"` and an `↗`, and the panel's own note says once, in words, that these leave the site and often land on a page to look through rather than on the map.

- **"Open their map" became "Open their map page", on a measurement.** Across the 76 authorities in the directory, **not one** network-map URL ends in `.pdf` — 46 have no extension at all, one `.aspx`, one `.html`, 28 no URL. So there is no shape a checker could use to tell "the map" from "the page the map is on", and the honest label is the one true in every case. Telling them apart needs a field the register does not have: buses-data OA-381. The Cambridgeshire and Peterborough row is the example — it is graded as publishing a whole-network map and its own note says the six Better Buses PDFs are precept routes.

- **"No map published through this portal covers X" now says "covers X yet"**, which is what the other branch of the same function has said since it shipped.

- **A resident who wants a map of their village has a door that fits them.** All three "ask for one" links pointed at `/apply.html`, which opens *Tell us a little about your organisation* and requires an organisation name and type — and the branch shown to the reader with the weakest answer offered that door and nothing else. They now lead with `/contact.html?kind=map-request&place=<name>`, which preselects the reason and prefills the place into the message, with the organisation door named second rather than dropped. `map-request` is a new value in `MSG_KINDS` so these asks are countable instead of filed as general enquiries. The place goes in the message **body**, not the placeholder: a placeholder is not sent, and a reader answering "yes please" would otherwise arrive as a map request naming no place.

- **The join is checked, not asserted.** A link naming a `kind` is a claim about three other files — the option in `contact.html`, the whitelist in `src/http/helpers.js`, and the prefill in `contact-kind.js`. `test-directory.mjs` now checks all three against the URL the code actually writes, and `prove-red-directory.mjs` gains six arms (14–19) that put the page back the way it was this morning, each watched go red.
