title: "The audit's P0 block: two public pages that were empty, and a deployment nobody could see"
---

`Development Docs/technical-audit_2026-08-25.md` in `buses-data`, findings N1, N2, N5, N6, N7 and N10. PR #90; live as `072c467`. (N9 landed in `buses-data`, N17 and the skill-side half of N10 in `claude-skills`.)

- **`/maps` and `/m/<slug>/services` now arrive with their content in them.** Both were shells whose bodies were built in the browser, so `curl https://busmaps.uk/m/st-ives/services` returned **4,716 bytes whose entire body was the word "Loading…"**, and `/maps` returned 4,479 bytes with **no link to any map**. Nineteen `/services` URLs are in `sitemap.xml`, indexing had been switched on four days earlier, and both pages drew their content from `/api/public/*` — which `robots.txt` forbade crawlers to fetch. The site was publishing those pages and blocking the only way to fill them. With JavaScript they were excellent, which is exactly why nobody had looked: the `<head>` had been correctly server-rendered since P8a, so the pages looked finished. **The test is `curl`, and the body rather than the `<head>`.** Measured after: `/m/march/services` 4,716 → **15,883 bytes with 7 route sections**; `/maps` → 18 crawlable map links.
- **The markup is shared, not written twice.** `public/js/shared/map-card.mjs` and `services-view.mjs` are plain ES modules with no DOM and no Node imports, imported by `src/server.js` **and** by the browser as `type="module"`. A second server-side copy of the same templates would have been drift waiting to happen, and this repo has been bitten by that shape often enough to say so. The client now renders only when the server left the page empty — it checks `#services.children.length`, so it reads what was actually delivered rather than a flag that could disagree with it.
- **`?q=` is server-side, which makes an old claim true for the first time.** `public-maps.js` has said since P9 that "the form is a real GET to `/maps` and works with JS off". It did not: nothing on the server had ever read `q`. It does now, hits and misses both. The B8 rule that search queries are never logged followed the feature onto `/maps` — **and the Caddy half is not closed**, which the code says out loud rather than leaving to be discovered: Caddy's access log records the full URI, and filtering it is a proxy change deserving its own deploy.
- **`robots.txt` narrowed** from a blanket `Disallow: /api/` to the five private prefixes, so `/api/public/*` is fetchable. `test-indexing.mjs` asserts the *negative* — that the blanket rule has not come back — because a future tidy-up would keep the positive assertions and break only that one.
- **`X-App-Version` on every response, from every route, without JavaScript.** The live site was found one commit behind `main`, and the missing commit was PR #89's NaPTAN attribution — a correction whose whole value is being public. Establishing that took a headless browser: closing the previous audit's S4 had (correctly) gated `gitSha` out of `/health`, and the only remaining surface was a `<meta>` tag injected by a script. **A security fix had quietly removed an operational control.** A build identifier is not a secret; the business counts, the object-store path and the exact sharp/libvips versions that S4 was really about stay gated. The consumer is `status.js`'s new Deployment row in `claude-skills`.
- **Sign-in links come from `PUBLIC_BASE_URL`, not `req.headers.host`.** A request carrying `Host: attacker.example` produced a genuine sign-in email whose link handed the single-use token to the attacker's server. It never landed — Caddy's site block matches two hostnames, so a spoofed Host never reached this process — but that was the *entire* mitigation: an implicit property of a proxy config, asserted by no test, that disappears the moment anyone adds a wildcard site, a staging hostname, or exposes `127.0.0.1:5180` to debug something. `baseUrl()` already existed and already preferred `PUBLIC_BASE_URL`; the auth links were simply not going through it. All three hand-built absolute URLs in `server.js` now do.
- **A malformed cookie is a 401, not a 500.** Reproduced against production: `Cookie: cbm_session=%` returned **500** where the control returned 401. `decodeURIComponent` throws `URIError` on a bad percent-escape and the throw escaped the `preHandler` — for *every* cookie on the request, not just ours, so one stray `%` on any unrelated cookie took the whole signed-in app down for that browser, across `/api/`, `/app`, `/auth/` and `/metrics`, with no diagnostic and no hint that clearing cookies was the cure. Falling back to the raw value is the right repair rather than dropping the cookie: a session token is base64url and has nothing to decode.
- **Ops tokens are Bearer-only and compared in constant time.** `?token=` also worked, and the Caddyfile enables an access log recording the full URI — so every use wrote a live credential in clear into a file that is in no backup, rotated by nothing here and under no retention rule. The tell that it was always wrong: this file's own log serialiser already stripped the *search query* on the reasoning that "an access log counts as a log". The query form is **removed**, not deprecated; `deploy.mjs`, its only caller, now sources the host's `.env` on the remote side so the token is not on an `ssh` command line either. `crypto.timingSafeEqual` replaces `===` for both tokens.
- **`engine/package.json` declares its licence.** It carried none at all while every file beside it is BUSL-1.1, which reads to an SPDX scanner as unlicensed.
- **A new gate, and it was watched fail.** `scripts/test-ssr.mjs` drives the real shells through the real renderers and asserts that the delivered HTML carries the catalogue and the services — not a `grep` over `server.js`, which would certify that the code contains a call rather than that the call works. Renaming `id="headline"` in `services.html` fails it. The shell helpers **throw** on a missing id for the same reason: a silent no-op is how an empty page ships unnoticed. `npm test` is 14 suites.
