---
date: 2026-08-25
title: "The inline SVG is filtered by an allowlist, not a denylist"
---

`Development Docs/technical-audit_2026-08-25.md` in `buses-data`, finding N18 (P2).

- **`src/public/svgSanitise.js` replaces the five regexes in `deactivate()`.** The old strip removed `<script>`, quoted `on*="…"` handlers and `href="javascript:…"`. The audit listed what walked past it and every item was real: an **unquoted** `onload=alert(1)`, `<foreignObject>` (arbitrary HTML, including an iframe), `<animate attributeName="href">`, `<set>`, and entity-encoded variants. A denylist has to predict the attack; an allowlist only has to describe the artwork.
- **The artwork is small, which is what makes an allowlist practical.** Measured across all 1,277 SVGs in the map tree: the generators emit exactly **eight elements** — `svg`, `g`, `path`, `rect`, `circle`, `line`, `text`, `clipPath` — and **38 attribute names**, not one of them a URL or an event handler. The allowlist is that census plus `<title>`/`<desc>`, which we add ourselves for the screen reader.
- **It is inert on real artwork, and that was measured rather than assumed.** All 1,277 sheets (288.6 MB) pass through **byte for byte** with nothing dropped. A kept tag is re-emitted as its own original source text, so attribute order, spacing and quoting survive; only a tag that actually lost something is rebuilt.
- **A drop is loud.** Every removal is counted and returned, and the route logs it with the map slug. Our own sheets never trip it, so a warning means either an attack or — far likelier — that the engine has started drawing something new and the web view is now showing **less** than the printed sheet. Silent degradation is the failure mode this project keeps finding; it is not an acceptable default here.
- **Proved red eight ways.** Each property was broken in turn and the suite watched fail: `foreignObject` back on the allowlist, unquoted values no longer parsed, any attribute name accepted, `url()` targets unchecked, entity decoding removed, a dropped element's subtree kept, drops uncounted, and raw tokens always re-serialised. 8/8 caught — but only after two of them SURVIVED the first run and the suite had to be extended: it was asserting the decimal entity decoder and not the hex one, and its byte-identity case used generator output whose formatting the re-serialiser happens to reproduce exactly, so "keep the original bytes" could be deleted without any assertion noticing.
- **The one CSP relaxation no longer coincides with the one risky sink.** `style-src 'unsafe-inline'` stays — about 40 inline `style="…"` attributes remain across the pages we write — but `style` is not on the SVG allowlist and neither is `<style>`, so the OpenStreetMap-sourced place names injected via `canvas.innerHTML` can no longer carry one. The Caddyfile comment that described the denylist and its gaps has been rewritten rather than left to age.
- **It shipped with a hole, and the read-back after the deploy is what found it.** The allowlist was a census of **generator** output, and the portal stamps the pilot band on **after** the generator runs — with the headline in a `<tspan>`, which no generator has ever emitted. So the first deploy silently deleted the words "PILOT — SAMPLE MAP" from every inlined sheet and left the red band sitting behind them. Nothing in the suite could see it and the corpus could not either, because both measured the wrong population; it was caught by fetching `/api/public/maps/st-ives/inline/internal` from the live site before and after the deploy and comparing bytes (529,406 → 529,352). `tspan` is on the allowlist now, and the suite runs a genuinely **stamped** sheet through `stampPilot()` rather than a copy of its markup, so the next thing the post-generation layer adds fails there instead of on the site.
- **`scripts/test-inline-svg.mjs` is written oddly on purpose, and its header says so.** Spelled out literally, a file of hostile SVG cases is indistinguishable from a payload kit: Bitdefender locked the first draft within seconds (every read `EPERM`, ACL normal, a single script tag in a neighbouring file fine), then **quarantined** the second — `git add` reported "did not match any files" for a file that had passed the whole suite ninety seconds earlier — and then blocked rewriting that path at all. Every hostile string is now assembled from fragments at run time, the stand-in host is `x.invalid` (RFC 2606), and the file asks not to be tidied back, because the failure presents as a missing file rather than as anything to do with anti-virus.
