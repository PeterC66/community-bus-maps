title: "The repo has been public for eight days and six documents still said private"
---
`gh repo view PeterC66/community-bus-maps --json visibility` answers **PUBLIC**. It has answered that since **2026-09-03**, when this repository and `claude-skills` were made public so that GitHub would stop billing their Actions minutes — a change recorded at the time in `buses-data`'s own `CLAUDE.md` and in two `CHANGELOG.d/` fragments from 2026-09-04, both of which say plainly that *this one is public*. Six places in this repository went on saying the opposite, `CLAUDE.md` line 7 among them, and nothing could have caught it: repository visibility is a property of the GitHub account, not of the tree, so it survives `actions/checkout` in exactly the wrong direction — every checker here reads a clone, and a clone of a public repo and a clone of a private one are the same bytes.

- **`CLAUDE.md` said `Private repo, Business Source License 1.1`.** The licence half was correct and still is; only the visibility half was wrong. It now states the date, the reason (Actions billing) and the consequence a session actually needs: **source-available, not secret — assume everything committed here is world-readable.**
- **`docs/CONVENTIONS.md` justified a real practice with a constraint that has expired.** *Read the POST-merge run, not the PR's own green checks* was argued from *branch protection is not available on a private repo without GitHub Pro*. Branch protection is free on a public repository, so the feature is now available and simply is not switched on — `gh api repos/PeterC66/community-bus-maps/branches/main/protection` answers `Branch not protected` and `.../rulesets` answers `[]`, both checked on 2026-09-11. **The advice is unchanged and its status is not**: it was a constraint, it is now a choice, and the paragraph says which and names the setting that would close the gap. A rule that outlives its stated reason is worse than one with no reason written down, because the next reader re-derives the wrong conclusion from it.
- **`docs/ROADMAP.md` contradicted itself by thirty-two words and fifty-five lines.** The open licensing follow-up called the map-content question *moot in practice while the repo is BUSL-1.1/private*, while the Data hygiene bullet in [Key facts for continuation](../docs/ROADMAP.md#key-facts-for-continuation) already read *never enter this (public) repo*. That contradiction is how the sweep found the file. The follow-up now turns on the licence alone, which is what was ever doing the work.
- **`docs/H1-operations-handbook.md`, `docs/DOCUMENTATION-PLAN.md` (twice) and `PRODUCT.md` are corrected the same way**, each keeping the BUSL-1.1 → Apache-2.0 clause it already carried. `DOCUMENTATION-PLAN.md` gains the sentence that matters most of the six: **the no-PII rule in `docs/` was never resting on the repository being closed** — PII is private by living outside git, in the local-only ops folder, and every one of these documents should be written for a stranger to read.
- **What was left alone, deliberately.** Every *other* use of "private" in this tree is still true and untouched: the `buses-data` repository really is private (which is why `DEPLOY.md` is right that its inherited CI reds are billed, and why the directory panel vendors a field projection rather than the survey's notes), the ops folder really is local-only, and a saved map version really is a private draft until it is reviewed. `CHANGELOG.d/` fragments are a dated record of what was believed on the day and are not rewritten.
