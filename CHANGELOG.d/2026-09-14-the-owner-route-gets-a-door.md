---
date: 2026-09-14
title: "The owner route gets a door"
---

- **Giving a customer their first map now has a button.** `POST /api/admin/maps/:id/owner` has been complete since 2026-08-30 — step-up gated, quota-checked, `map.reassign` audited, search-index bumping, stored-sheet reconciling — and until today **nothing in the client called it**. A grep across the whole of `public/` found one `/owner` hit, in `app-dashboard.js`, and it renders the owning organisation's name on a card. The admin map view at `/app/maps/<id>` now carries a *Who owns this map* panel with an organisation picker, visible to admins only (buses-data OA-364).

- **It was built for a mistake and is now used for a transaction, which is why it had no surface.** `docs/R1-create-map.md` documents the route under **"Wrong customer"** — a repair for an import that named the wrong organisation, added to replace "a re-import plus an archive, or a hand-written `UPDATE` against the live database". Handing a real customer their first map is not a repair: it is the single act that makes a registration visible to a reader, because until it happens the customer's flags apply to nothing and the sheet in their bus shelter still says nobody published it.

- **The confirmation names what the move costs, per direction, because a picker without one is a trap.** Moving a map to an organisation lists five consequences built from that particular move: the badge on the public sheet changes hands and the stored sheets are re-stamped for the new owner's sample band; it spends one of their map slots, with their current count shown; their people gain the sign-in that edits it and the old owner's lose it; "published" and "sent back" emails follow the owner, and a *Spotted a problem?* report — which lands in our own inbox either way — becomes theirs to be passed to. A sixth appears only when the receiving organisation is **suspended**: the public queries admit `c.status = 'active'` only, so the map leaves the public site. Un-owning lists its own three, starting with the public page returning "not found" at once.

- **Every sentence it reports is one the response carried.** The sibling fault the same day was an approve button that told the admin "The invite has been emailed" over a response that never said whether it had. So the new owner is read from `body.customer`, not from the option that was picked; the stored-sheet outcome is read from `body.restamped`, which the route deliberately fills with `{ error: true }` when the reconcile fails *after* the reassignment has committed — a 200 that carries bad news, and the panel says so and names `scripts/restamp-renders.mjs --apply`; and the whole thing is then checked against a re-read of `/api/maps/:id`, whose disagreement is reported rather than hidden. A request that never comes back does **not** claim nothing happened, because a write whose response is lost may still have landed.

- **The route's `restamped` now also reports `seen`.** Without it a caller cannot tell "no stored sheet needed changing" from "this map has no stored sheets at all", and the panel would have had to guess between two sentences that are not both true. Measured on an unbuilt map, which is exactly the case the first draft got wrong.

- **Both refusals are handled as refusals.** A 403 `step-up-required` keeps the selection, says nothing has moved — true, because `requireStepUp` runs above the first database call — and says to sign in again in another tab and press the button again. A 409 `code: 'quota'` shows the server's own sentence and points at the Customers tab. The stale-sign-in warning is also shown **before** the attempt, from `/api/me`'s `session.stepUpFresh`, for the reason `review.js` gives about publishing: the server has always known, and the only thing that ever mentioned it was the 403 at the end.

- **A test asks the one question the server-side tests could not, and it has been seen to refuse.** `npm run test:owner-picker` joins three files: something under `public/` posts to the route as `src/routes/admin.js` declares it, every `$('ownerXxx')` the script drives is an id the page carries, and the client still reads both refusal codes and `restamped`. `npm run test:prove-red-owner-picker` breaks each of those in a scratch copy across eight arms — including deleting the POST, which is OA-364 itself — and requires the test to name the assertion it broke. 88 tests, 0 failed.
