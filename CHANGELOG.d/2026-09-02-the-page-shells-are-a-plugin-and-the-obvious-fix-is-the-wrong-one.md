title: "The signed-in app's page shells are a plugin, and the obvious way to guard them is the wrong one"
---

The second half of the editor spine and the last section cut under `buses-data` OA-231, Tier 4.4. Ten HTML shells moved to `src/routes/pages.js` under the prefix `/app`; `server.js` 1,573 → 1,489 lines, from **3,371** before the admin cut. The route table is byte-identical to the pre-split snapshot, and the comparison is **70 lines out, 66 in** — the nine removed lines are the nine per-handler `if (!req.user) return reply.redirect('/app/login.html')` the hook replaced.

- **These are pages, not API, which is why they are a second plugin rather than more of `src/routes/editor.js`.** Every refusal here is a redirect; every refusal there is a 401 or a 403. One file, one refusal vocabulary.
- **One redirect, not nine — and the fault it prevents has happened here.** `/app/review-services.html` was reachable by anybody until 2026-08-20 because it was a static file with no route of its own (technical-audit_2026-08-19 S7), the clearest single case in that audit. A page shell that loses its guard does not fail loudly; it serves. The sign-in page is the one exception and declares it as route config the hook reads — a hook that redirected the login page to itself would loop.
- **The hook is only part of the decision.** Four pages carry a further ROLE check in the handler: `/app/admin` and `/app/changelog` to admins, `/app/review` and `/app/review-services.html` to approvers and admins, `/app/maps/:id/diagram` to admins. They redirect rather than refuse, so a signed-in editor following a stale link lands on `/app` rather than on an error. `test-pages-plugin.mjs` asserts every role in both directions, because a suite that only checks refusals passes just as well when a page is broken for everyone.
- **THE OBVIOUS FIX IS THE WRONG ONE, and there is now an arm that proves it.** "Guard the `/app` prefix" reads like the same rule as "guard the plugin's routes" and is not: a Fastify hook is scoped to the routes of the plugin that declares it, so `/app/app.css` is still served by `@fastify/static` to anybody — which it must be, because the sign-in page needs its stylesheet before anyone is signed in. `prove-red-pages-plugin.mjs`'s last arm installs a global `onRequest` hook on the path, exactly as somebody tidying up would, and the suite has to notice. 7 mutations, 7 caught for their own reason, control green.
- **`/app/maps/:id/diagram` came from the P7 section, not from the editor spine.** That is the prefix rule rather than a land grab: this plugin registers under `/app`, so a page shell left behind in `server.js` would make the prefix a claim that is not true. P7 keeps its API routes; one page moved, and its admin check moved with it.
- **What moved out BEFORE the cut.** A route file may not reach into `server.js`, so `ROOT_DIR`, `PUBLIC_DIR` and `VIEWS_DIR` are now `src/paths.js` — the sibling of `src/db/paths.js`, importing nothing but `node:path` and `node:url`, so importing it cannot open a database or create a directory — and `xmlEscape()` is now in `src/http/helpers.js`, shared by `sitemap.xml` and the admin changelog page. `server.js` no longer needs `fileURLToPath` at all.

`npm test` 50 run, 0 failed, 2 excluded (48 before).
