title: "One shape for an unexpected failure, and one file that reads the environment"
---

The last two items on OA-231 (`buses-data` OA-224 Tier 5, portal-src F4 and F7).

**F4 — the envelope.** 24 `try` blocks and 11 explicit `.code(500)` cover the failures this code knows about, and every one answers `{ok:false,error}` — the envelope the client reads in 128 places. Anything **else** fell through to Fastify's default `{statusCode,error,message}`, which is the wrong way round: the shape a client can rely on was guaranteed for the errors somebody had thought about and not for the ones they had not. `ok` was absent, so `if (!r.ok)` — the standard test in this app's own JavaScript — read `undefined` and took the **success** branch on a crash.

- **The decisions live in `src/http/errors.js` as pure functions, and that is not tidiness.** The 5xx branch is the branch nobody can reach on purpose: every route that can fail already catches its own failure, and Fastify refuses a route added after `ready()`, so a test cannot provoke it through the app. As functions they can be handed a deliberately horrible error — one carrying a file path and a token — and the answer read. A 5xx now says *Something went wrong at our end*; a 4xx Fastify raised keeps its own message, because somebody chose those words for a reader.
- **The 404's `code` is an interface, not a detail.** `check-live-routes.mjs` (the previous entry) tells a ROUTER 404 — the route is gone — from a HANDLER 404, which is what `/m/:slug` must return for an unpublished slug, and it did that by matching Fastify's default message string: a discriminator nobody had declared, that adding this handler would have broken silently, and whose failure mode is the loudest false alarm available — *every route on the live site is gone*. The body now carries `code: "route_not_found"` **and** repeats Fastify's old wording as a compatibility shim, so the two changes can land in either order. Both are asserted, and the shim's assertion is what will make somebody notice when it is time to drop it.
- A browser navigating to a dead URL still gets the not-found page; `Accept: application/json` gets the envelope. `scripts/test-error-envelope.mjs`, 20 assertions.

**F7 — the environment.** `process.env` was read in eight files: 20 reads outside `src/config.js`, including every secret, while `config.js` held three flags. Nothing could answer *what does this deployment read, and what happens when it is unset?*, and the fail-direction of each variable — which this codebase argues about carefully for `PILOT` and `INDEXING` — was invisible for the rest.

- **Accessors, not constants, and the reason is measured.** `test-operator-token.mjs` UNSETS `OPERATOR_TOKEN` at runtime and asserts the token stops working; a module-level snapshot would have made that assertion pass for the wrong reason for ever. Callers that legitimately snapshot at load (`BASE_URL`, `DEV_LINKS`, `STALE_AFTER_MONTHS`) still do, by calling the accessor once at module scope.
- **`PUBLIC_BASE_URL` was read three ways.** `http/helpers.js` stripped every trailing slash, `email/notify.js` stripped one, `worklist/index.js` stripped none — so a value ending in `/` gave the app `https://busmaps.uk/maps`, the email the same, and the operator's worklist `https://busmaps.uk//maps`. Three spellings of one value is the shape `sessionTokenHash`/`tokenHash` had in Tier 3.3. One reading now, the strictest, asserted.
- **`scripts/test-env-inventory.mjs` is a census, not a list.** It asks of every file under `src/` whether it reads `process.env` at all and allows exactly three, each with its reason in the test and in `config.js`: `config.js` itself, `db/paths.js` (it exists so a script can learn a path without importing anything that opens a database) and `version.js` (build stamps read by code that must not depend on config). It also asserts the converse — an accessor nothing imports is a variable somebody stopped reading — and that the three ops tokens fail **closed** when unset.
- **`prove-red-operator-token.mjs` found the move itself**: three arms reported STALE ANCHOR, which is a broken harness reporting itself rather than a quiet pass, and is exactly why `damage()` counts its matches. Re-anchored, and all 10 mutations are caught again for their own reason.

`npm test` 52 run, 0 failed, 2 excluded (51 before).
