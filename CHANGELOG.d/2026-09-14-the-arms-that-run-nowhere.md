title: "The sweep for arms that run nowhere, and the parser one of them was hiding"
---

- **The sweep portal PR #298 asked for was run, by measurement rather than by grep.** `npm test` was run three times in a throwaway worktree — once as a fresh checkout, once as the full laptop, and once with `BUSES_DIR` pinned at a path that does not exist — and the assertion lines diffed. The third run was needed because the second was leaky: `scripts/lib/buses-dir.mjs` falls back to a hard-coded `C:/u3a St Ives/Using AI/Buses`, so deleting `.env` does **not** hide the map tree, and the first diff wrongly reported `test-build-warnings.mjs` as running in CI. Four files carry arms a fresh checkout cannot reach: `test-build-warnings.mjs` (4 assertions), `test-complexity-band.mjs` (9), `test-inline-svg.mjs` (2) and the pack half of `test-landmark-tiers.mjs` (8) with its 3 prove-red mutations. `npm test` runs in `test.yml` and in no other workflow, so none of those arms had ever run in CI.

- **One of them was hiding a live defect, and it is the one whose arm ran nowhere.** `readBuildWarnings()` was written on 2026-08-30 against `N warnings, M blocking.`; `build_log.js` in the engine gained `, and K measurement(s).` the same day (buses-data OA-118), and the lane measurement is unconditional. The old regex required the full stop straight after `blocking` and matched none of the longer lines. Measured over all 900 `build-warnings.txt` files on the map tree: **595 parsed as `null`** — including **both** of the only two files in the estate's history that report a BLOCKING warning, and **all eight** towns' current renders. With the fix, 5 parse as null, and those five are genuinely headerless files where `null` is the right answer. The zero-warning line (`No warnings — every generator ran clean.`) now reads as a real zero; the absent file still reports `null`, which is the one case that must.

- **The half that needs no map tree now runs everywhere, on captured output rather than invented output.** `scripts/fixtures/` holds verbatim engine files: five `build-warnings.txt` covering every shape the sweep found, and eight `complexity.json`, one per town, covering all three bands. That distinction is the whole point — cases 1–4 of each test were files the test wrote, and a synthetic fixture can only confirm what whoever wrote the parser already believed. CI gained **21 assertions**. Falsified rather than assumed: with the old regex restored, 6 of the new build-warnings arms go red with no map tree and the run exits 1; with the `No warnings` branch removed, the other 2 go red; emptying `fixtures/complexity/` reddens the vacuity guard rather than passing over an empty loop.

- **The live-tree arms are kept, because they ask a question a capture cannot.** A capture answers *does the parser handle what the engine HAS written*; only the live tree answers *…and what it writes today*, which is exactly the change this capture just failed to notice for fifteen days. Both are kept and the skip note now says which one did not run.

- **The laptop arm was also an anecdote, and that is fixed too.** `test-build-warnings.mjs` walked depth-first and stopped at three files, which on this tree meant three versions of one place's sheet, all three in the one shape that still parsed. It now takes the newest report per town — eight reports, eight shapes. The comment claiming no real file on the tree carries a blocking warning was false and is corrected; one of the two that do is now the committed fixture.

- **A skip note was consoling the reader with cover that does not exist.** `test-inline-svg.mjs` said its corpus half was covered by `npm run verify`. It is not: `verify:area`, `verify:place` and `verify:defaults` re-render and byte-compare, and the string `sanitiseSvg` appears in none of them — the sanitiser is exercised in that file and nowhere else in the repository. The note now says the committed excerpt is the only cover this half has.

- **What still runs nowhere, stated rather than left to a skip line.** The pack half of the landmark tiers and its 3 mutations need a generator run over a real map pack and cannot be supplied by a fixture; `test-inline-svg.mjs`'s 13-sheet corpus is breadth over the committed excerpt, not a different question; and the two live-tree arms above are deliberate. `check-vendored.mjs` runs as `--no-skills` in the preflight and says so in its own output. 86 tests, 0 failed, in both conditions.
