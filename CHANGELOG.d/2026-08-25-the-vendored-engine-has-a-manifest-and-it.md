title: "The vendored engine has a manifest, and it found a file that had been stale for four days"
---

`Development Docs/technical-audit_2026-08-25.md` in `buses-data`, finding N14 (P2), and the July 2026 engine-deduplication proposal that asked for the same thing.

- **`engine/vendored.json` names every `.js` under `engine/`** as `vendored` (with the skill path it came from and a SHA-256 of its CRLF-normalised bytes) or `portal-owned` (a wrapper with no counterpart in the skill, and a reason). `scripts/check-vendored.mjs` checks it; `scripts/test-vendored.mjs` runs inside `npm test`. Until now the only drift check lived in the SKILLS repository, so a developer working only in `community-bus-maps` — the natural way a second person onboards — had no way to discover that `engine/icons.js` had diverged from its source, and CI had no way either.
- **Writing it turned up three vendored files nobody was watching, one of them wrong.** The skills-side check listed eleven files by hand; the tree holds sixteen. `engine/area/gen_external_busway.js`, `engine/area/gen_external_radial.js` and `engine/place/gen_internal_place.js` were byte-for-byte copies that no gate had ever compared — and `gen_external_radial.js` had been stale since 2026-08-21, missing the March X32 badge-overlap fix and the `sheetQr` default. It is the fallback `scripts/import-map.mjs` copies into any area payload that carries no generators, which is every payload the skill has staged since 2026-08-04, so the next area import would have shipped a sheet with a badge under a lozenge and no QR code. Re-vendored in this change; already-imported maps hold their own copy and are unaffected.
- **A file the manifest does not name is a FAILURE, not a silence.** That is the whole difference between this and the list it replaces: a hand-maintained table is a list you must remember to extend, and the four days above are what forgetting looks like. Both checks now read the same manifest, so they cannot disagree about which files exist — `status.js` in the skills repository lost its hard-coded eleven and reports `UNLISTED` too.
- **The two checks ask different questions and neither can answer the other's.** The portal's runs anywhere, including CI, and asks *has the portal's copy been edited since it was vendored*. The skills-side one runs where both trees exist and asks *has the source moved on without us*. Where the skill tree is absent the source half is skipped **by name** rather than passing quietly.
- **Proved red before being trusted**, eleven ways: an edited portal copy (EDITED), a source that moved (DRIFTED), an unlisted file (UNLISTED), a deleted one (MISSING), a portal-owned entry with no reason (NO-REASON), a named source that does not exist (NO-SOURCE), an absent skill tree (skipped, and *not* reported as verified), and a CRLF-only difference (still OK, because `core.autocrlf` must not read as drift). 26 assertions. The same two mutations were then walked through the real board: `status.js` exited 1 with `DRIFTED` and `UNLISTED` rows and returned to 0 when they were reverted.
