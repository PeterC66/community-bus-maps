title: "The tube-map diagram is PARKED — hidden behind one flag, off by default, and proved off in every reader"
---

Peter's decision of 2026-09-10 (buses-data OA-297): remove every mention of the tube-map diagram option from the portal so that it neither blocks nor affects anything we or customers do, in a way that lets it come back (buses-data OA-298). Nothing is deleted.

- **One flag.** `TUBE_DIAGRAM` in `src/config.js`, off unless `1`, fails towards the parked state the way `PILOT_MODE` fails towards the honest one. The catalogue row's `portal` is a getter on it, read at each use so a test can flip it. Declared in `compose.yaml`, `.env.example` and `docs/DEPLOY.md`; unset on the live host.
- **Every reader already honoured `portal: false`, and none had ever seen it.** `defaultOutputs()`, `effectiveOutputs()`, `outputsForClient()`, `chooseOutputs()` and `publicOutputs()` skip the row; `resolveGen()` now refuses an unoffered output outright, which is the one choke point the pin editor's `diagramAvailable()` also passes through, so an admin gets *no diagram to tune* rather than a working editor on a hidden sheet.
- **"Not offered" now reaches the file routes.** Read from outside on 2026-09-10 after the St Ives output had been switched off: `/api/public/maps/st-ives/inline/internal-diagram`, `/preview/internal-diagram` and `/internal-diagram.svg` all answered **200**, because `PUBLIC_BASES` held every base the catalogue had ever known. It is `publicBases()` now, derived from offered outputs, and all three routes refuse a parked base.
- **The customer sees nothing.** The editor draws only offered rows, so the locked row and its *Ask us* button are gone; `POST /api/maps/:id/diagram-request` is 404 while parked; the refusal message on `PATCH /api/maps/:id/outputs` names the output generically, since the only thing it can now refuse is the boarding plan. The homepage card, the pricing line, the FAQ entry, the AI answer's sentence, the examples footnote, the terms sentence and the customer guide are removed — *Five outputs* is *Four*.
- **Tested off, tested on, and falsified.** `scripts/test-parked-diagram.mjs` runs with the flag unset and asserts the catalogue, a payload that opts in, the public read model, the three file routes against a published scratch map that enables the diagram and holds the file, the request and expert routes, and a copy gate over `public/` and `views/` whose banned phrases name the option and not the word (the external sheet is still *the onward-travel diagram*). `scripts/test-p7.mjs` sets the flag on before its first import and keeps the request-only lock, the grant and the wrapper proved for the return. `scripts/prove-red-parked-diagram.mjs` runs the parked test with the flag on and requires the offered-state assertions to go red, and re-inserts the pricing line into a scratch copy and requires the copy gate to name the file.
- **The self-sufficiency prove-red moved its coverage mutation.** Its control expected four arms and its case 3 deleted `internalDiagram`; the committed St Ives fixture carries three sheets since buses-data `a71bbf6a`, so the control asserts three arms and no diagram arm, and case 3 deletes `internalSchematic` and expects two.
- **Nothing in `engine/expert/` changed**, and `/ops/ready` still checks the diagram files are present: the return needs no re-vendor.
