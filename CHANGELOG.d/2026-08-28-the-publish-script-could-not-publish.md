date: 2026-08-28
title: "The publish script could not publish, and said it was the cookie"
---

- **`accept-publish-batch.mjs` has been unable to publish anything since 2026-08-25, and the failure read as a bad credential.** CSRF arrived that day in `8787a72`, which edited this very script — but only for that commit's *other* change, the hashing of stored session tokens. The commit's own note says why the gap was invisible: the client side was fixed by patching `window.fetch` once "rather than twenty-six call sites edited", which covers every browser caller and no script. From then until today the script could list proposed updates (a GET, unguarded) and could not accept, submit, approve or publish a single one.
- **It failed at the first POST with a 403 whose body says *"reload the page and try again"*** — advice for a browser, from a tool that has no page — **and the script classified it `auth failed`.** That is the expensive half: `authFailure` deliberately aborts the whole remaining run on the reasoning that a dead session will only fail 17 more times. So one CSRF refusal reported itself as 18 failures and a bad cookie. Found on a real 18-map round, where the pasted cookie was demonstrably fine: it had just listed all 18 pending updates.
- **The fix is four lines and the reasoning behind them is the point.** The portal double-submits — a `cbm_csrf` cookie that must equal an `x-csrf-token` header — and the server does not remember the token, it only checks the two halves match. What makes that safe is that a cross-site attacker can neither set a cookie on our origin nor read one; a first-party CLI already holding the session cookie is not that attacker and may mint its own pair. So the script does, per run.
- **And a 403 whose `code` is `csrf` is no longer called an auth failure.** It means the opposite of one: the session is alive and the request was malformed. It now reports itself, with the contract it expected, instead of aborting the run as a credential problem — because the whole cost of this bug was three days of a dead publish path reading as a bad cookie.
