date: 2026-09-18
title: "Approving an organisation refused for the wrong reason and told the operator to use a screen that has never existed"
---

- **`POST /api/admin/applications/:id/approve` now asks about the ORGANISATION before it asks about the person, and that reordering is the whole fix.** It used to ask only whether the contact email had an account, and answer `chair@… already has an account. Approve this organisation manually or ask them to sign in.` Peter met that on the first real registration, on a second application row for an organisation registered the night before. The refusal saved him — approving would have written a **second `customer` row for one organisation**, each with its own quota, leaving the map handover ambiguous about which owns the sheet — and then sent him looking for a screen that does not exist: there is no `POST /api/admin/customers` and no create-customer control anywhere under `public/` or `views/`. A duplicate now says it is a duplicate, names the customer that already exists by id, and says to **reject** it (buses-data OA-367).

- **The order matters more than the wording, and there is an assertion that holds it.** On the row Peter met, both guards would fire — the organisation is registered *and* the contact has an account — so a route that still asked the email first would pass every sentence-level check. `scripts/test-approve-application.mjs` therefore also approves a duplicate organisation whose contact is **somebody new**, which only the organisation check can see at all. Before the fix that request returned **200** and wrote the second customer row.

- **The genuine collision is refused honestly, and it names nothing.** A person who already holds an account applying for a NEW organisation is a real case — and it is not approvable here by any wording, because `user.email` is `UNIQUE` and a user row carries one `customer_id`, so the data model cannot say *this person is also the first editor of a second organisation*. OA-367 offered a choice between adding a route and naming a script; there is no script that does this job — `import-map.mjs --customer` creates a customer as a side-effect of importing a map and attaches no user, and `create-admin.mjs` refuses an email that already exists — so the refusal names neither, says plainly that no screen approves it, and names what an operator can actually do. The test asserts that the message contains no `.mjs` and no `scripts/`, because a refusal naming a script that does not do the job is the same fault in a new coat.

- **The three writes are one transaction now.** `insertCustomer` → `insertUser` → `setApplicationReviewed` ran in bare sequence, so a throw between the first and the third left an **orphan customer with no users and the application still pending** — recoverable by hand only, and invisible until somebody counted customers. `scripts/delete-map.mjs`, one folder away, has had `BEGIN`/`COMMIT`/`ROLLBACK` since it was written; the habit existed in this codebase and had not reached here. It is now importable as `withTransaction()` in `src/db/index.js`, which joins an outer transaction rather than throwing on a nested call (SQLite has no nested `BEGIN`, and a helper that refused one would make a caller's safety depend on who called it) and refuses an async function outright, because that would `COMMIT` at the first `await` with the work still outstanding.

- **The arm that had never been seen is forced for real, through the route.** `test-approve-application.mjs` installs a `BEFORE INSERT` trigger on `user` that `ABORT`s one address — no stub and no monkey-patch, so what runs is the route's own path against the real database — and asserts no customer survives, no user was written, and the application is still pending. Run against the pre-fix code the suite fails **14** assertions, including that one: the orphan customer was there, with no users, exactly as described. The email stays deliberately outside the transaction; sending is not rollback-able, and a link issued for a customer row that never committed is worse than one that arrives a moment late.
