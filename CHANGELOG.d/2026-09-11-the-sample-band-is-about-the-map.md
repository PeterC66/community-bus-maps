---
date: 2026-09-11
title: "The sample band is a claim about the map, so it now asks which map"
---

- **The red band said something no admin could stop it saying.** `PILOT — SAMPLE MAP · Made to test the system. Not published by any organisation. Do not rely on it for travel.` is printed across the top of every rendered sheet, and the middle sentence is a fact about the **map** — who published it — while the only thing gating it was the site-wide `PILOT_MODE`. There was no value on any customer that stopped it appearing above that customer's own badge. True of every sheet on the site the day it was written, and false the moment the first external organisation registers, with no code change in between (buses-data OA-320).
- **`customer.is_sample` is the answer, and `PILOT_MODE` still beats it in the off direction.** A sheet carries the band when the pilot is on **and** its customer publishes sample maps; `customer.is_demo` forces it on whatever else is set, because the invented councils `scripts/seed-demo.mjs` creates must stay labelled after the pilot ends. `isSampleCustomer()` in `src/render/pilotStamp.js` is the whole rule, and every way of not knowing — no customer row, a `SELECT` that forgot the join, a caller that passed nothing — answers *sample*, the same direction `PILOT.on` itself defaults in.
- **The column defaults to 1, so this should move nothing.** Live is 18 published maps and exactly one organisation, `busmaps-uk-pilot` (`/api/public/maps`, 11 September). Every sheet was a sample before and is a sample after, so the correct outcome is that nothing changes — and **that, not the green suite, is the acceptance test**, because a change like this can only be wrong by moving a sheet it should not have moved. On the laptop's development store `node scripts/restamp-renders.mjs` reports **31 stored sheets inspected, 0 would change**. The live store is the VPS and is not this one: the same dry run is a deploy step, and any number other than zero there is the bug rather than the migration working.
- **An admin turns it off beside the watermark, because they are the same moment.** The console's customers table gains a *Sample maps* column next to *Watermark downloads*, and both titles now say they are flipped together when an organisation stops being ours and starts being theirs.
- **Reassigning a map reconciles its stored sheets.** The band is baked into the bytes — right for it, wrong for its two neighbours: `draftStamp.js` had to move to serve time because a version's state changes on every publish, and `watermark.js` because the answer differs between two viewers at the same instant. A map's publishing organisation changes on one audited admin action, so `src/routes/admin.js` restamps that map as part of the reassignment, and a failure is reported rather than swallowed — a map quietly keeping the old band over its new owner's badge would look exactly like a success.
- **`scripts/restamp-renders.mjs` asks once per map instead of once for the site,** and gives up the "paths only" import that kept it from opening the database. That is stated at the head of the file rather than quietly reversed: it is an operator-run script against the live store, and `src/render/pilotReconcile.js`, which does the work, still imports paths only and takes the answer as an argument.
- **Ten mutations were watched go red before any of this was believed.** The suite is green today for a reason unrelated to the code being right — every customer on the site is a sample customer, and `sample` defaults to true, so a render path that forgets to ask behaves identically to one that asked. `npm run test:prove-red-sample-band` breaks each arm on purpose, including one that restores the exact pre-OA-320 code, and requires the *named* assertion to object rather than any assertion at all. The control stays green. One arm was reported SURVIVED on its first run and the arm was wrong, not the suite: either no-op guard in the reconciler absorbs the damage alone, so both have to go for the difference to exist.
- **And the threading is checked as a JOIN, because a default of true is invisible.** `scripts/test-sample-band.mjs` sweeps all 21 `generateSvg`/`renderVersion`/`preview` call sites in `src/` and `scripts/` and requires each to have passed `sample:`, passed `stamp: false`, or hold a written exemption; an exemption whose call site has gone is itself a failure. Widening that sweep from the wrappers to `generateSvg` itself found four call sites the first version had hidden, including `renderMap()`, which turns out to have no callers at all.
