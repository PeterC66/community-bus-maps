date: 2026-09-01
title: "A $FIXTURE_DIR entry names the town, not a folder that expires"
---

- **The warning added on 2026-08-30 was accurate, prominent and ignorable, and the run went red afterwards anyway (OA-211).** Every entry in `.env`'s `FIXTURE_DIR` is a path shaped `Areas/<Town>/S5-render/v6.59_2026-08-30_0606`, and a path with a version number in it goes stale at every rollout — so the ordinary local run gated a different pack from CI and reported `DIFFERS` about a fixture that was perfectly good. A false red on a determinism gate is the one kind of red that must never be routine: it teaches a reader to skip a red on the check whose whole job is to be believed.
- **The evidence that repointing is not the fix is that it recurred inside a day.** `.env` was repointed at three current renders on the morning of 2026-09-01 (St Ives v6.67, Huntingdon v3.55, Beaconsfield v1.58); by that evening the landmark-chooser rollout had made **all three** stale again, and the first run of the new resolver advanced every one of them — v6.67→v6.68, v3.55→v3.56, v1.58→v1.59 — before reproducing all four sheets byte-identically.
- **So the entry is now read as naming the TOWN, and `resolveFixtures()` gates that town's current render.** `scripts/lib/newest-render.mjs`, called from the resolver rather than from any one gate, for the same reason `warnIfBehindCommitted()` is sited there: six scripts resolve fixtures, and a check each caller has to remember is one a seventh caller will not make. `.env` stops carrying a fact that expires, and nobody has to edit a file after every rollout — which matters because the person who would have to is Peter.
- **The answer comes from `manifest.json`, never from a directory listing.** Sorting `S5-render/` as strings puts `v6.9` after `v6.67` and `v10.0` before `v2.0`; that bug has already shipped twice, in `status.js`'s freshness check and in the old area-fixture recipe. `stages.S5.latest` names the current run outright and `runs[]` says where it lives.
- **THIS AMENDS A CLAIM THE 2026-08-30 ENTRY MADE IN AS MANY WORDS**, so it is worth being exact about what changed. That entry said *"an advisory check that quietly repointed a fixture would have destroyed the very property the env override exists for"*, and it was right about the check it was describing. The property is that `FIXTURE_DIR` aims the local gate at the **live render tree**, which is where a regression surfaces first and is therefore stronger than the committed pack. This resolution only ever moves an entry FORWARD and only WITHIN that same tree — it never falls back to the committed pack, and advancing is the only direction anybody has ever wanted, because the variable exists to gate a render newer than the committed fixture during a rollout. What the earlier entry ruled out was substituting *quietly*; this prints both versions, the map, and where the answer came from.
- **Every way of not knowing leaves the entry exactly as written**, which is what keeps the older warning covering everything it used to: no `manifest.json`, a `latest` the manifest lists no folder for, a run folder that is not on this disk (`S5-render/` is gitignored, so a fresh clone has none), or a path with no `S5-render` segment — which is why `PLACE_FIXTURE_DIR`, pointing straight at a committed `_portal-fixture` pack, is untouched. The first two print why they could not resolve; the last two are correct silences, because a notice on every good run is a notice nobody reads by Friday.
- **Falsified in both directions, in the harness that already existed.** `npm run test:prove-red-fixture-drift` grew six cases and now drives thirteen scratch trees; **four of the six new ones are cases where nothing may move**, because substituting when it should not is the dangerous direction — that would gate a pack nobody asked for while printing that everything reproduced. Watched red under a mutation that deletes the advance: all four assertions in case 7 turn.
- **And the mutation caught a weak assertion, which is the whole reason to run one.** *"the substitution names the map"* read the child's entire output — which also contains the older `BEHIND` warning, and that names the town too — so it stayed **green** with the advance deleted outright. It now reads the substitution line alone. This is the second time an assertion in this harness has been satisfied by a neighbouring clause, and both times only a mutation found it; a verdict cannot tell you which clause produced it.
