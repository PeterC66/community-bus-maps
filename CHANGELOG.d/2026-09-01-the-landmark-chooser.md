date: 2026-09-01
title: "A screen for choosing landmarks, because the worksheet failed on its first reader"
---

- **The 171-row markdown worksheet is replaced by a page.** Peter read `Areas/High Wycombe/poi-worksheet.md` as the local editor it was written for — the trial run its covering note asked for — and it failed on three structural counts: 171 rows times three choices is daunting arithmetic; it offered *two* ways to answer the same question, a write-in column and a JSON block, with neither marked as primary; and a write-in column is the wrong instrument even on paper. The framing was ours too. A local is not thinking about how a symbol crowds out other type — they are thinking about which places people navigate by, and that judgement barely needs the bus routes at all.
- **`/app/maps/:id/landmarks` asks it their way.** Three choices per place reading **Must show**, **Show if there is room** and **Do not show**; a rename field that folds away until you are looking at a row; per-category bulk answers, which is what collapses 171 decisions into about nine plus the handful anybody cares about; and the town's own street network underneath with every place drawn on it, pannable and zoomable, so the judgement is made looking at where each place actually is. `must` / `may` / `miss` remain the engine's keys and the reader never meets them.
- **The map is deliberately not the sheet, and says so under itself.** It is drawn from the same `roads_geo.json` the sheet is built from, so the streets are real, but the sheet's projection, rotation and focus fisheye are not applied. A picture that looked like the printed sheet without being it would invite a judgement about crowding from the wrong drawing; **See the real sheet** runs the actual generator and answers that question properly.
- **It writes `internal.poiTiers`, and that is not the tick box the editor already had.** The editor's `internal.pois[k].hide` is a RENDER-time override: the symbol is still selected, still reserves its 4.2 mm box, still anchors the placer and still counts in `ci-reference`, the byte gate and the quality ledger. A tier is applied by `poi_select.js` at SELECTION, before any of that. A third radio wired to `hide` would have told a customer they were making room while making none. Measured through the portal's own preview: one `miss` takes a real sheet from 22 drawn POIs to 21 and 1,178 bytes off the SVG.
- **A saved `hide` is shown as *Do not show* and rewritten as a tier on the next save**, which is a visible change to an existing map — the space is finally given back, so the sheet re-arranges. The page says so before you save it. Saving carries the map's other overrides with it, because `sanitizeOverrides()` rebuilds the object from scratch and posting only this page's key would have discarded the customer's route colours.
- **The key universe a save is validated against is now the union of what is drawn and what COULD be drawn, and this one would have shipped.** `enumeratePoisFromDir()` lists a map's POIs by rendering it and scraping `data-key`. A `miss` in a map pack's own `routes.json` never reaches that SVG, so validating against it would refuse the very key keeping the place off the sheet — the classification dropped on the next save, the POI back, nobody told, and the monthly proposed-update re-apply the worst place for it. Measured rather than reasoned, and **narrower than the first draft claimed**: a `miss` in the *customer's* layer is still enumerated, because that render uses base overrides. The case that bites is the one every map reaches the moment a town's answer is exported back into its source data.
- **Falsified before it was believed.** `npm run test:prove-red-landmark-tiers` breaks ten guards on a copy of the tree and requires each to be caught by the assertion named for it; the control asserts that both halves of the suite actually ran, because the key-universe half skips without a real map pack and a skip would have reported three mutations as SURVIVED for a reason that is not the guard's fault. Two real faults came out of writing it: a blank rename discarded the whole entry, tier included, and the suite crashed rather than failing when a guard dropped an entry, which meant the harness could not say which guard had objected.
