- **`scripts/deploy-caddy.mjs` takes `--dry-run` (buses-data OA-228).** It copies the `Caddyfile` to the VPS with `scp`, installs, validates and reloads it over `ssh`, then reads the live headers back. Its look-first flag was `--print`, a spelling no other VPS script uses, and `--dry-run` was silently ignored: a run meant as a look deployed. It now reads `confirm('remote')` from `scripts/lib/cli.mjs`: the default is unchanged, `--dry-run` says it is a dry run and prints the commands with the host and key it read, and connects to nothing; `--print` still works; `--yes` is accepted and changes nothing, because the script asks no question. The `DEPLOY_HOST` refusal still runs under `--dry-run`. New `scripts/test-deploy-caddy.mjs` (`npm run test:deploy-caddy`) points the child at a host under `.invalid`, puts shim `scp`, `ssh` and `curl` first on its PATH off Windows, and uses a real run as the control; against the old script it fails 12 of its 21 checks. [DEPLOY §3a](docs/DEPLOY.md#3a-security-headers-live-in-the-caddyfile-and-they-are-deployed-separately) names the flag. The eighth of the nine scripts OA-228 lists; one pull request each.
- **Deploy history, written before the deploy per [DEPLOY §3b](docs/DEPLOY.md#3b-the-deploy-history-entry-is-written-before-the-deploy-and-merged-with-it).** This pull request's merge is the commit that goes live. The server does not import `deploy-caddy.mjs`, and the `Caddyfile` itself is not redeployed, so nothing a visitor or a customer sees changes: no schema, route, UI or engine change.
