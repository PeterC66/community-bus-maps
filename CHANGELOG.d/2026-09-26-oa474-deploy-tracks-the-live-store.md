title: "The deploy tracks the live map store to the engine it shipped"
---

- **`npm run deploy` now runs `track-engine.mjs` on the live container as its step 5b (buses-data OA-474).** A delivered map's pack carries its own generator, so a deployed re-vendor reached no stored map until `track-engine.mjs --apply` had run on the host. That was two raw `ssh` commands only Peter could run, and nothing on the bus-work board said when one was owed; five re-vendors (#373, #381, #384, #386, #389) were waiting at once. Every re-vendor goes live through the deploy, so the deploy is where the step belongs, and it runs on every deploy because it is a no-op (`0 BEHIND`) when no engine file moved.
- **The verdict is the read-back, not the write.** Step 5b runs `--apply`, then the report form, and fails on the second run's exit code: a pack still behind, or any `?` row (a pack naming a generator this engine does not vendor, or an `engine-source.json` that will not parse). A failure does not stop the sign-in test, since the site is already live, but the deploy exits non-zero at the end. It re-renders nothing and changes no published byte.
- **`npm run test:deploy-track-engine` runs the real `track-engine.mjs` against scratch stores** through an `ssh` stand-in, and was seen to go red when the step was made to trust the `--apply` exit code instead of reading back. [DEPLOY §4a](docs/DEPLOY.md#4a-a-re-vendor-is-not-finished-until-the-live-store-has-been-tracked-and-the-live-number-is-not-the-laptops) and §3b now say the deploy does this; the two `ssh` commands stay there for reading the store without deploying.
- **Deploy history, written before the deploy per [DEPLOY §3b](docs/DEPLOY.md#3b-the-deploy-history-entry-is-written-before-the-deploy-and-merged-with-it).** This merge is the commit that goes live. `scripts/deploy.mjs` runs from the laptop's checkout, so the new step runs only on a deploy made AFTER that checkout is on this merge. Its first real run should bring forward every pack left behind by the five re-vendors above. No schema, route, UI or engine change.
