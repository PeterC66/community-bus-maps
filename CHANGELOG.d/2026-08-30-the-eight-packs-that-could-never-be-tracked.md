date: 2026-08-30
title: "The eight packs that could never be tracked"
---

- **`track-engine.mjs` skipped eight of the eighteen live maps on every run, and it was every town's external sheet (OA-143).** A map's data pack carries its own copy of the generators and `generateSvg()` runs THAT copy, so the tracker keeps them level with `engine/` after each re-vendor. It can only do that where the pack's filename says what the file is — and an area pack stores its external generator as `gen_external.js` while the portal vendors two of them. It refused to guess, which was right: overwriting a busway map with the radial generator is a silent corruption discovered at the next render. The cost of refusing was that **an engine fix to a town external reached nothing** until the map was re-imported, while the ten place maps got the same fix for free. OA-130's *track, not freeze* was two-thirds true, and the missing third was a whole sheet type on every town we publish.
- **The answer is now recorded where it is known, which is at import.** `import-map.mjs` picks the file it stages, so it writes what it picked into `engine-source.json` beside the generator; `track-engine.mjs` reads it and tracks the pack like any other. **Nothing infers, on any run** — a pack that does not declare is skipped exactly as before, and the report now says which of the two it is and how to record it.
- **A payload that carried its OWN generator is deliberately left undeclared**, and that is a feature rather than a gap: it may be hand-edited, and a hand-edited generator must never be overwritten by the vendored one. Only the staged case is recorded, so the tracker stays off the rest.
- **`backfill-engine-source.mjs` is the one-off for the packs that predate this, and it is the only place permitted to work the answer out.** It reads TWO independent signals and requires them to agree. *The map's own data*: `gen_external_busway.js` dereferences `D.busway[0]` at load, so a `routes.json` with no `busway[]` cannot be a busway map — not "probably is not", cannot. *The stored generator*: the busway file dereferences `D.busway[`, the radial file never mentions `.busway`, asked of the pack's own copy whatever engine version it is frozen at. **When they disagree, nothing is written and the pack is reported** — a migration that resolves its own ambiguity by picking a side is the guess this row exists to refuse.
- **A hash comparison was the obvious approach and is the wrong one.** These packs are several engine changes behind by construction — that is the entire reason they need tracking — so byte-equality answers "no" to both candidates and tells you nothing.
- **Measured on the live store before writing anything, and both signals agreed on all eight**: no `busway[]` in any `routes.json`, and no `D.busway[]` in any stored `gen_external.js`. Then applied there: **8 recorded, 0 undecided**, and `track-engine.mjs` went from *38 current, 0 behind, 8 skipped* to **46 current, 0 behind, 0 skipped**. Every generator in every live pack now tracks the vendored engine.
- **Twenty checks and seven mutations**, `npm run test:engine-source` and `npm run test:prove-red-engine-source`, the second wired into `verify.yml` ahead of nothing in particular because it needs no fixture and no database. Everything this change adds is a REFUSAL, and a refusal is the hardest thing to keep honest: code that has quietly stopped refusing passes every "it tracks the declared one" assertion while silently doing the corruption. So each guard is broken on purpose and required to redden **the assertion that claims to be about it** — a mutation caught by the wrong test is reported as `WRONG CAUSE`, which is a hole of its own. The busway arms matter most: every town on the board is radial, so a tracker or a migration hardcoded to radial is right about all eight and wrong in principle, and only a fixture that is genuinely busway can tell the difference.
- **The harness found a bug in itself on its first run**, which is the usual argument for writing one. It split each result line on an em dash to read the failing assertion's name — and several assertion names contain em dashes, so every expected name was truncated at its first one and two genuine catches were reported as `WRONG CAUSE`. A harness that misreads its own subject's output is the fault it exists to catch, one level up.
