date: 2026-09-01
title: "The landmark chooser's map-click handler had never once fired, and four other things the third viewing turned up"
---

- **A feature that was written, shipped, documented and inert.** `landmarks.js` has had a handler for *click a place on the map to open its row* since the page's first day, with a comment calling it "the other half of *show me where*". It has never fired. The pan handler eleven lines above takes `setPointerCapture` so a drag that leaves the stage keeps panning, and **pointer capture retargets the following `click` to the `<svg>` itself** — so `closest('[data-key]')` was null every single time. Nothing could have caught it: the handler is not wrong, no test asserts that a handler fires, and the map panned perfectly throughout. It surfaced only because the reader asked for a feature that already existed. Proved rather than reasoned, in a browser, with two identical SVGs — one taking capture and one not: with capture `e.target` is `<svg>` and the lookup is `NULL`; without it, the circle. Selection now comes off a pointerdown/pointerup tap test that reads the target *before* capture is taken, which also stops a drag ending over a mark from selecting it.
- **And the same pointer arithmetic was wrong in a way nobody had reported.** The pan and the zoom anchor converted pixels to map units with `VIEW.w / stage.width`. The SVG is `xMidYMid meet`, so a roughly square town on a wide, short stage is scaled to FIT and letterboxed — measured on the live page, a 0.0303 × 0.0349 view box on a 422 × 163 stage scales by 4,672 px per unit where that expression claims 13,922. A drag moved the map about three times too fast sideways and a wheel zoom drifted off whatever was under the pointer. Everything crossing between the two spaces now goes through one `stageMetrics()`, and `zoomAt` anchors on a user-space point rather than a fraction of the stage. It only surfaced because road labels are the first thing on this page that has to land on an exact pixel.
- **"left as they are" was two populations under one name.** The tally's third figure is `total − must − miss` — every row the map will show if there is room — which adds an answered *Show if there is room* to a row nobody has reached, and describes the history of neither. It is also a claim about the past that the page cannot check: a place that arrived as *Do not show* and was moved to *may* has not been left as anything. The three figures now use the legend's own words and the line below is left to answer progress on its own.
- **The default answer still could not be given in one click.** `set` was only ever written from the list's `change` event, and a radio that is already checked fires no `change` — so recording *Show if there is room* meant clicking *Must show* and clicking back. That is the answer the previous round went to some trouble to make recordable. A `click` listener on the options now records it whether or not the value moved; `setTier` is idempotent, so the two handlers need know nothing about each other.
- **The sheet's own pictograms, from the file the sheet actually renders with.** `/api/poi-glyphs` serves the twelve glyphs from `engine/icons.js` with the sheet's own arguments — charcoal, grid set — and that is not merely a copy of what a map draws: generators are vendored per map, but no map vendors a sibling `icons.js`, so every render resolves it through `SKILL_ASSETS`, which `renderMap.js` always sets to `ENGINE_DIR`. One file. They appear beside every row and every category heading, and on the map past a zoom threshold, where the tier's disc becomes the ring around the glyph so the answer stays readable once the mark is a picture rather than a colour. The headings gained the reader's words at the same time — they had been printing the engine's keys, so a local editor was reading "gp" and "townhall". A new assertion reads the category list back out of `classify()`'s own source and requires every one of them to have a glyph, because that join has nothing else holding it together.
- **Enough road names to orient by, and the obvious rule was measured first.** The basemap endpoint has always sent `n`, the way's name or ref, and the client threw it away. Labelling only the MAJOR roads — the obvious cut — was measured across all five portal maps before anything was written, and yields **two** labels on the map the reader is actually looking at (`A40` and `London Road`) against 178 names across its ways; the other four give 7, 16, 20 and 23. So the layer ranks by length instead, drops anything off screen, drops a name already placed, drops a box overlapping one already taken, caps at fourteen and can be switched off. Ranking by length has a property that fell out rather than being designed: the fitted view names the through-roads, and zooming in reveals the side streets as the long ones leave the view.
- **What is falsified.** The declutter, the tap test and the tally's wording are lifted out of the browser file and run, the way the editor's round-trip already was — a declutter especially, because a label it wrongly drops looks exactly like a road with no name, so nothing about the drawing can tell you it is wrong. `prove-red-landmark-tiers.mjs` breaks each of them plus the glyph join on purpose and checks WHICH assertion objects: 16 mutations, each caught by the assertion named for it, with the control green.
