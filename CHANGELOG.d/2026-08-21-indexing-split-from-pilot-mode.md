---
date: 2026-08-21
title: "Indexing split from pilot mode"
---

- **`robots.txt` is no longer keyed on `PILOT_MODE`.** The two were one switch, and that conflated two different claims: the pilot banner and the sheet band say *"this is a pilot, do not mistake it for a service"* — honest, and worth keeping while it is true — whereas `Disallow: /` says *"nobody may find this at all"*. Tied together, the only route to being discoverable was to stop admitting it was a pilot. Indexing is now its own flag, `ALLOW_INDEXING` (new `INDEXING` export in `src/config.js`), **off by default** for exactly the reason `PILOT_MODE` is on by default: forgetting an env var must fail towards the private state, not the exposed one. Note the corollary — `PILOT_MODE=0` alone no longer enables indexing.
- **Nothing else was needed in order to be discoverable.** `sitemap.xml`, the per-map server-rendered `<title>`/description/canonical/Open Graph/JSON-LD (P8a) and the `/m/<slug>/services` text pages were all already built and working; this flag was the only thing standing in front of them.
- **The policy moved into `src/public/robots.js` as a pure function.** `src/server.js` listens on import, so the route could only ever have been asserted by grepping the source — which certifies the code, not the behaviour. `scripts/test-indexing.mjs` (new, wired into `npm test`) calls the same function the route calls and checks the real bytes in **both** flag states: a test that only ever checks the disallowed state carries on passing after the flag stops working. Watched go red by inverting the condition (3 of 12 checks failed, exit 1) before being trusted, then confirmed end to end by booting the server and fetching `/robots.txt` with the flag set and unset.
- **`docs/PILOT.md`'s teardown instructions corrected.** They listed `src/config.js` as a whole-file delete; it now also exports `INDEXING`, so following them literally would have silently un-indexed the site at the exact moment it stopped being a pilot.
