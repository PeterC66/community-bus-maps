title: "The landmark chooser could not speak, and had been showing a quarter of every icon"

Six reports from Peter after working through High Wycombe's 171 places on the live site. Five were faults; the sixth was a question, and its answer is now in [*We are getting a customer — start here*](https://github.com/PeterC66/buses-data/blob/main/Documentation/README%20-%20How%20to%20handle%20a%20customer.md). Nothing here touches the engine, the safe subset or any map's bytes — it is all the chooser's own front end.

**Every message this page has ever tried to show was invisible, at five sites, since the day each was written.** Peter's report was "I did *Copy for our records* and could not tell if it worked", and the answer was not that the notice sat at the foot of a long panel. `.notice` in `app.css` is `display: none` and `.notice.show` is what reveals it; `admin.js`, `editor.js`, `review.js`, `branding.js` and `diagram.js` all write `'notice show ' + kind`. `landmarks.js` wrote `'notice ' + kind` and then tried to reveal the element with `style.display = ''`, which removes the inline style and hands the question straight back to the stylesheet that says none. Two more sites reached for the `hidden` attribute, which a class rule beats just as easily. So the save result, the "could not reach the server" error, the export confirmation, the *Must show* soft-cap counter and the old-tick-box explanation were all dead — and so was `showWarnings()`, whose entire purpose is to name the *Must show* choices the generator could not seat, and which OA-216 introduced as "the cheapest place to learn a Must show cannot be seated". Nobody has ever read one. Everything now goes through one `showEl()`. **It was found in a browser and could not have been found anywhere else**: it is a join between a class name in one file and a rule in another, and neither file is wrong on its own.

**About a fifth of each pictogram was showing (OA-220's sprite, used two ways).** A `<use>` of a `<symbol>` with no `x`/`y`/`width`/`height` takes the defaults `x=0, y=0, width=100%, height=100%`, so the symbol's viewport lands at 0,0→20,20 in whatever user space it is dropped into. The list wrapped it in `<svg viewBox="-10 -10 20 20">` — the symbol's own box — which shows only the glyph's top-left QUARTER, pushed into the bottom-right of the icon. The map layer never had this because `drawPoints()` writes the placement out longhand. The row's box now starts at the origin, and the test states the rule rather than the string: *the box the row draws into must start at 0 0*, because that is where a bare `<use>` puts its content.

**A row with no name at all.** `classify()` in `poi_select.js` returns `t.name || ''` for pharmacies and GP surgeries — deliberate, because the sheet never prints those names, so an unnamed chemist costs the paper nothing. It cost the chooser everything: the row arrived with an empty title, and a reader was asked to rule on a chemist they could not identify. High Wycombe, Huntingdon and St Neots have one each. `displayName()` now gives it *Unnamed pharmacy* in italic — deliberately not a guess at the name — with a line saying the map's data has none and pointing at the row's own rename box. The underlying key collision (a candidate key is `cat + ':' + name`, so two unnamed chemists in one town would share one key and one answer — latent today, measured across all eight towns) is buses-data [OA-234](https://github.com/PeterC66/buses-data/blob/main/Development%20Docs/open-actions/OA-234.md).

**The name column had been squeezed to its minimum width, and the row said what the heading already said.** The three answers spell themselves out in full — that wording is the design of this page — and they measure about 530 px together, against a list panel of 480 px in the two-column layout and about 730 px in the one-column one. So `auto 1fr auto` pushed the name to min-content and every row became five lines of one word each. The row now stacks by default and returns to one line only when its own container is wide enough for both, which is a container query rather than a media query because the deciding width is the panel's, not the window's. And *"symbol only — its name is never printed"* now appears only in a MIXED group; in a group where nothing prints its name the heading's own tagline had been repeating on all thirteen rows.

**Answering a row now takes it out of the filter it is sitting under.** *Not looked at yet* went on showing rows you had just looked at until you clicked the chip again — because a single answer called `paintRow()` and only the bulk buttons rebuilt, so one list obeyed two rules depending on which control you used. The old behaviour was deliberate (a rebuild used to throw the reader back to the top of 145 rows) and the anchor is what makes the new one safe: `listAnchor()` now declines to anchor to a row the coming rebuild will drop, so nothing above the reader's eye moves. Measured on the real 145-row set — answering the middle option, which does not change the tier and is the hardest case, removed the row with the list's `scrollTop` unchanged to the pixel.

**And *Copy for our records* says so on itself.** It flashes *Copied ✓* on the button, names how many places went; when the clipboard is unavailable — it needs a secure context, so over plain http it throws every time — the block lands in a read-only textarea, already selected, instead of a one-line notice. Carrying that answer back into the town's own `routes.json` is still a paste, and automating it is buses-data [OA-233](https://github.com/PeterC66/buses-data/blob/main/Development%20Docs/open-actions/OA-233.md).

**Seven new mutations in `prove-red-landmark-tiers.mjs`, 23 arms in all, each caught by the assertion named for it.** One survived its first run and the check was wrong, not the arm: renaming the stylesheet rule to `.notice.shown` still satisfied a search for `.notice.show`, because the shorter string is a prefix of the longer one.
