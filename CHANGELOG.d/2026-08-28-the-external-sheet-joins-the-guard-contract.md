---
date: 2026-08-28
title: "The external sheet joins the guard contract"
---

- **`gen_external_radial.js` now participates in `STRICT_GUARDS`, so a town external that declines to draw something can stop a publish.** Until today only `gen_internal.js` and `gen_boarding.js` required `strict_guards.js` at all, which meant "STRICT_GUARDS is live" was true of a third of the sheets this portal renders and nothing said which third. The radial generator has exactly one site that declines to draw something the config asked for — the `howToUse` panel, whose own comment already reads *"NOT DRAWN rather than cover one"*. `build_log.js` has always classified that message BLOCKING off the words; what was missing was the **exit code**, and the exit code is the only signal this portal's publish path reads. `renderMap.js` looks at stderr only when the status is non-zero, so on the success path — the one that matters — the whole stream went public unread.
- **It starts green, and it has been watched fire.** Swept across all 20 committed maps first: nothing refuses, on any sheet, so no existing map changes behaviour. Then forced, by giving Huntingdon a 267 mm `howToUse` panel that cannot fit anywhere clear: exit 0 with the flag unset, exit 1 with `STRICT_GUARDS=1`, the banner printed, and the artwork written either way — which is the contract's design, because a build that refused something is still worth looking at.
- **Byte-neutral, and proven so rather than assumed.** `refuse()` writes to stderr and `report()` sets an exit code; neither touches `out()`. Every byte gate across the 20 maps and both portal fixtures still PASSes, and the file was run against a real town pack with `SKILL_ASSETS` pointed at this repository's `engine/` to prove the new `require` resolves in the portal's own layout and not merely on a laptop — the vendored tree lists `strict_guards.js` among the files it needs, and `npm run test:selfsufficient` agrees.
- **The other three unguarded generators deliberately do NOT adopt it, on evidence.** `schematize_internal.js` and `diagram_internal.js` have no refusal path at all: their only non-zero exits are hard preconditions that already `exit(1)`, which is a stronger signal than a refusal, not a weaker one. `gen_external_busway.js` is dormant — no map can use it and none does.
