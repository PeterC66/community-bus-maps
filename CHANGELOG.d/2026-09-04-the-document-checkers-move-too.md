title: "The document checks stop needing a token, because those checkers moved too"
---

buses-data OA-246, and the same move again. This morning's `docs` job — added hours earlier under OA-227, the first time anything had ever read this repository's documents — checked **buses-data** out with `CROSS_REPO_PAT2` to fetch `check-tables.mjs` and `check-doc-links.mjs`. That token expires on **22 November 2026**, and on that day the documentation checks would have stopped here and in `claude-skills` at once. Both checkers, their two falsification harnesses and `lib/tracked-docs.mjs` have moved into **`claude-skills/tools/`**, beside `check-file-hygiene.mjs`, which made the identical move five hours earlier. The checkout below now carries **no secret at all**, and nothing in this repository's CI fetches a documentation checker across a token.

**The rule travels and the scope stays home.** Both checkers used to resolve their corpus relative to their own location, which meant buses-data's folder names. They now resolve it against **the repository they are run FROM**, and each repository declares its own at a dotfile at its root. This one already had `.doc-links.json`, for the `resolveFromRoot` its assembled `CHANGELOG.d/` fragments depend on; it declares no `dirs`, and a repository that declares none gets the **widest** scope — its whole tree. So the invocation lost its `--root` and gained a `working-directory`, and the numbers are unchanged: **332 table rows across 21 documents, and 127 documents plus 4 archived for links** — the last `docs` run on `main` before the move read exactly that, and this branch reads 128 because of the fragment you are reading. Measured either side rather than inferred from a green run, which was the acceptance test the row set. (On a laptop the link count is one higher again: with no `dirs` declared the checker walks the tree and finds the generated, gitignored `CHANGELOG.md`, which `actions/checkout` cannot produce. A working tree holds things no CI run can see — the same asymmetry the hygiene checker was opened about.)

**And that test earned its keep.** The first cut read a repository's declaration only in the default mode, treating `--root <dir>` as *this is a fixture, not a repository*. This repository's CI passed `--root <its own root>` — so it lost `resolveFromRoot` and reported **24 live links dead**, while every case in the harness stayed green, because those fixtures are temp folders that genuinely have no declaration. Two questions look identical from inside a checker and are not the same: *what tree do I scan* and *whose rules am I under*. There is now a harness case where the tree named by the flag does carry a declaration.

**The `docs` job stays a job, which the row expected it not to.** OA-246 predicted these steps would fold into `test`, since `test` already checks `claude-skills` out for the hygiene checker. They cannot, and the reason belongs to this workflow rather than to the checkers: `test` checks this repository out at the workspace **root**, so the sibling `claude-skills/` checkout lands *inside* the tree. `check-file-hygiene.mjs` is unaffected because it asks git which files are tracked and the sibling is not; these two walk the disk, so a `--tree .` there would read another repository's documents into this repository's totals. A separate job costs nothing — Actions bills only private repositories and this one is public — and it keeps what a separate job is for: a failure in `test` cannot hide a documentation finding.
