date: 2026-08-31
title: "The declaration died with the data it described"
---

- **OA-143's fix lasted one evening on eight of the eighteen live maps (OA-199).** `engine-source.json` records which of the two vendored external generators a pack's `gen_external.js` is a copy of, because the filename cannot say and `track-engine.mjs` refuses to guess. It was written and verified on 2026-08-30, taking the tracker from *38 current, 0 behind, 8 skipped* to **46/0/0**. On 2026-08-31 the tracker read `38 already current, 0 BEHIND, 8 skipped` again, and `backfill-engine-source.mjs` said `8 to record, 0 already declared` — the same eight, every town's external sheet. The 21:53 batch that accepted and published eighteen maps is when they went.
- **Nothing maintained the record, and nothing could have.** `swapInProposedData()` archives the whole live data directory and moves the staged one in, then carries files back out of the archive — and that carry-forward list held **exactly one entry**, the expert's diagram pins. Only `import-map.mjs` and `backfill-engine-source.mjs` ever write the declaration; `grep` across `src/` finds no writer at all, so no server path could replace what the swap discarded.
- **A skip is not a failure, which is why nobody saw it.** `track-engine.mjs` prints a `·` line per skipped pack and exits 0. Anyone reading only the summary sees `0 BEHIND` and a green run. OA-130's decision was *track, not freeze* — one engine fix reaches every delivered map — and for eight maps' external sheet that had silently gone back to being false.
- **The two-line fix would have introduced the corruption the design exists to refuse, and that is the part worth reading.** A refresh is exactly the moment a town's layout can change. Carry a `radial` declaration onto a pack that now holds the BUSWAY generator and the tracker — which trusts a declaration *precisely so that it never guesses* — overwrites that generator with the radial file at the next re-vendor. So the declaration is now checked against the generator it describes before it is kept, using the same tell `backfill-engine-source.mjs` reads: the busway generator dereferences `D.busway[`, the radial one never mentions `.busway`. **A declaration that has stopped being true is dropped rather than carried** — absent means "nobody has answered", which the tracker already handles correctly and the backfill can repair, whereas a confident wrong answer is unrecoverable. The refusal is logged by name and reason on the accept path, because a pack that lost its declaration for a *good* reason is still a fact about that map nothing else would say out loud.
- **An entry naming a file the refreshed pack does not have is moot rather than wrong**, and is left alone. The declaration is dropped only on a genuine disagreement.
- **Seventeen checks and six mutations** — `npm run test:carry-forward` and `npm run test:prove-red-carry-forward`, both wired into `npm test`. `swapInProposedData()` had **no test of any kind** before this: the carry-forward list had never had to be right about a second entry, and the first time it was given one it was wrong within twenty-four hours.
- **The assertion that matters is the one about an ABSENT file.** A test that stages a payload carrying its own declaration and then finds a declaration in the live data goes green against a carry-forward list that does nothing at all. Every survival check stages a payload that does *not* carry one, because that is the case that actually happened.
- **The harness caught a hole in the suite on its first run.** The case asserting that a fresh payload's own declaration is not overwritten had the payload switch the pack to busway — so when the mutation deleted the existence guard entirely, the *verdict* refused the archived radial declaration and the assertion read that refusal as the guard working. It reported `SURVIVED`. Both declarations now name the same generator, which leaves the verdict with nothing to say and the guard as the only thing that can pass the test. One fixture answering two clauses is the recurring shape here, and only a mutation finds it.
- **The filename is duplicated between `src/maps/store.js` and `scripts/lib/engine-source.mjs`, deliberately, and the duplication is pinned by an assertion rather than by hope.** Neither module can import the other: `test-engine-source.mjs` builds a scratch world holding a copy of `scripts/` only, so a `src/` import would break the suite that guards the tracker, and importing the other way round would drag `src/db` — and a database migration — into scripts whose whole point is running without one. A mutation changes one literal and requires the suite to say so.
