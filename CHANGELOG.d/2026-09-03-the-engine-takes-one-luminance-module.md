date: 2026-09-03
title: "The engine takes one luminance module, and the place skill stops carrying its own resolvers"
---
- **`engine/wcag.js` is new, and it is the first vendored file this repository has been given because the audit asked for it by name.** `vendor-engine.mjs` copied the nine drifted files, `requireScan()` reported `wcag.js` UNRESOLVED — "required through SKILL_ASSETS by place/gen_internal.js" — and printed the exact `--add` command. That loop is the OA-224 Tier 3.6 work doing what it was built for: a new engine dependency used to arrive silently and throw at render time, and the byte gates could not see it because a gate compares output and a missing module never produces any.
- **Nothing drawn moved.** `verify:area` and `verify:place` both reproduce byte-for-byte through the vendored copies — six sheets across three fixtures, SVG and JPG. The skills-side byte gate held all 98 sheet verdicts identical to the baseline taken before the first edit, and the estate's 19 maps were re-stamped without a rebuild (`buses-data` `063e3de`); every one of those diffs is a single `"engine"` line.
- **`wcag.js` collects seven copies of the same three coefficients from five engine files, and names them apart rather than unifying them.** They were never one function: the raw weighted average of the sRGB bytes is a brightness proxy and is what every threshold in this engine is calibrated against (the 0.62 ink test, the 0.75 icon-plate test, the quality ratchet's 0.55 and 0.8); the WCAG relative luminance gamma-decodes first and is the only one a contrast ratio may honestly use; CIE Lab answers a third question, colour distance. Making them one formula would re-tune which icon plates go white and which sheets clear the ratchet, so it stays a separate, gated change.
- **Nine engine files re-vendored** — `icons.js`, `label_placer.js`, `engine_paths.js`, `area/gen_external_radial.js`, `expert/diagram_internal.js`, `expert/schematize_internal.js`, `expert/gen_boarding.js`, `place/gen_external_places.js` and `place/gen_internal.js` — and ten stored map packs brought forward with `track:engine`, so the next render of each runs this engine rather than the one it was imported with.
- **`engine_paths.js` gained a fourth arm and `place/gen_external_places.js` lost two private resolvers.** The place skill reached the shared engine its own way, including an absolute path that resolves on one laptop; that hop is now inside the one resolver, so the vendored place generator and the five town entry points carry the same six-line bootstrap, character for character, asserted by a test on the skills side.
