date: 2026-08-31
title: "The token reached .env and not the container — the warning was in the file nobody opens"
---

`OPERATOR_TOKEN` shipped an hour earlier, was written into the host's `.env`, and the deploy recreated the container. The live worklist still got a 401. The host's `.env` said 43 characters; the container said 0.

- **The `portal` service has no `env_file`.** Compose reads `.env` only to substitute `${VARS}` into `compose.yaml`, so a key that is not also named under `environment:` never reaches the container — however correct it looks in the file. The app takes its unset branch, the operator sees the value where they put it, and nothing anywhere says the two disagree.
- **This is the fourth time**: `ALLOW_SELF_APPROVAL` and `ALLOW_INDEXING` (2026-08-21), `BACKUP_RECIPIENT` (2026-08-25), and now this. `compose.yaml` has carried a capitalised paragraph about it since the second one.
- **The fourth was sprung by somebody who had read that paragraph earlier the same hour**, and that is the useful part. The warning is in `compose.yaml`, and `compose.yaml` is not the file you open when you add a config variable — you open `.env.example` and `docs/DEPLOY.md`, and neither of them said to go there. **A guard placed where the mistake is made is a guard; a guard placed where the mistake is explained is a comment.** Both documents now say it, and the paragraph is a check.
- **`npm run check:compose-env`.** Every `process.env.X` under `src/` must be named in the portal service's `environment:`, or in the Dockerfile's own `ENV` (which is why `HOST`, `PORT` and `DATA_DIR` need no line), or in the script's `EXEMPT` table **with a written reason**. The table is checked in the other direction too — an entry for a variable the app no longer reads is a finding, because otherwise the exemption list becomes where stale decisions go to be believed. In `npm test`.
- **Falsified against the real fault, not a synthetic one.** Deleting the `OPERATOR_TOKEN` line from `compose.yaml` makes it name that variable and exit 1; restoring the file makes it green again. It also carries four self-tests that run on every invocation — including one proving a variable under the *`backup`* service does not count as delivered to the portal — and refuses to report a verdict at all if any of them fails. The first cut of the script failed all four, because the dead-exemption sweep was also running against the synthetic fixtures; a checker that cannot pass its own controls has no business passing yours.
- **It found a second, latent instance while being written.** `STALE_AFTER_MONTHS` — how many months before a published map's data is labelled stale on the public pages — was reachable from nowhere: absent from `.env.example` and from `compose.yaml`, so an operator who set it would have changed nothing and been told nothing. Now named, empty meaning the built-in six.
