---
date: 2026-08-27
title: "The orphan river that stopped seven published maps from ever being updated"
---

- **Seven of the eighteen live maps could not be re-rendered at all, and had not been able to for about a year.** Measured on the live host on 2026-08-27 (OA-137): rendering every published map through its own entry point inside the container, eleven render and seven refuse. A refusal is a non-zero exit under `STRICT_GUARDS`, which `renderMap.js` sets on every render that goes public — an import, a customer preview, an accepted proposed update, a re-publish — so those seven **could not receive an update at all**. Nothing a member of the public could see was wrong: the stored sheets are served from disk exactly as approved. What was broken was the ability to produce a new version of them.
- **The cause is a default the engine invents, not anything in the maps.** `gen_internal.js` falls back to a single hardcoded feature when a map declares no `features[]` — `RJ.riverLabel || 'River Great Ouse'`, inherited from St Ives — and hands it `river_geo.json`, which for a place with no river in its walkshed is empty. A label with no line under it is exactly what `feature_labels.js` refuses to draw. The engine no longer invents it when there is neither a `features[]` nor any geometry. Byte-neutral on all 20 committed maps in the data repo and on both portal fixtures, because a feature hidden by an override was already skipped in the reserve pass and in the draw, so hidden and absent produced identical ink.
- **It survived because the fix for it was a side file, and side files do not survive delivery.** Each affected pack shipped an `overrides.json` whose entire content was `{"internal":{"features":{"river":{"hide":true}}}}`. That layer has to come through four hops to reach the render that matters — delivery out of the skill, import (where `import-map.mjs` stores it as `base-overrides.json`), engine tracking, and `mergeOverrides()` under the customer's own edits — and it did not survive all four. A default that has to be cancelled everywhere is a default in the wrong place, so the cancellation was deleted along with the invention.
- **The diagnosis first recorded was wrong in three ways, all of which are worth knowing.** The packs carry no `features[]` river entry to edit — the prescribed remedy addressed a key none of them contained. The seven are not "the places on the Great Ouse": two of them are Beaconsfield Simpson Centre and St Ives Bus Station, and every map names that river only because the label is a default. And there were no "five further refusals" on two maps — every one of the seven refused exactly **once**; the extra `panel:` lines come from a bare `stderr.write` in `services_panel.js`, have never been counted and have never blocked anything.
- **`engine/place/gen_internal.js` re-vendored, and `npm run track:engine --apply` run** so the stored packs run the fixed generator rather than the one they were imported with. Stored sheets are untouched; what changes is the next render of each map. `npm run verify` passes — area and place reproduce byte-for-byte, and both escape-hatch suites still find every hatch live.
- **The check that would have caught it now exists, in the skills repo:** `make-bus-leaflet/assets/render_sweep.js` renders every map's declared sheets under `STRICT_GUARDS=1`, composing the expert framing the way `renderVersion(id, {})` does, and `--drop-framing` renders as a delivery that has lost its side file. It takes the refusal count from `strict_guards.js`'s own banner instead of counting guard-shaped stderr lines, runs a store pack's **own** generator rather than the skill's (the portal does, and a sweep that did not would have called an un-tracked store clean — it did, once, before this was fixed), and reports `n/a` where a generator has no `STRICT_GUARDS` contract at all. Only `gen_internal.js` and `gen_boarding.js` have one, so no external, schematic or diagram sheet can currently refuse anything.
- **Nothing here was believed without being watched fail.** `tools/prove-red-sweep.js` restores the old default into a scratch copy of the engine and requires four outcomes: green with framing, green without it, the restored default **invisible** while the side file survives — asserted deliberately as a no-op, because that is why a year passed — and the restored default with `--drop-framing` reproducing the named seven and exactly seven refusals. Run against the local store, map 4 refused before `track:engine --apply` and rendered after it, which is the same sequence the live host needs.
