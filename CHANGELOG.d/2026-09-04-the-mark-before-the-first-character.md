title: "Forty-six byte-order marks, and the guard that will not let them back"
---

buses-data OA-241. A sweep of all three repositories for layout faults that confound an EDIT rather than a reader found **47 here, against 6 in buses-data and 2 in claude-skills** — and this repository held every one of the worst kind.

**Forty-six byte-order marks, in the files most likely to be edited.** `CLAUDE.md`, `README.md`, twelve `docs/*.md`, twelve `views/app/*.html`, `src/server.js`, all five `src/*/index.js` plugin entry points, six `scripts/*.mjs` and the five `public/app/*.js` bundles. A BOM is three bytes sitting **before the first character**, so it breaks any edit that matches on the start of a file, and it appears in no diff, no review and no test. Stripped in this change; `.ps1` files are deliberately exempt, because Windows PowerShell 5.1 reads a BOM-less file as ANSI and the first em dash added to a message string would be mangled at run time. `npm test` was 61/61 before and after, and `scripts/test-error-envelope.mjs` gained the final newline it was missing.

**The guard is in `.githooks/pre-commit` rather than CI, and the reason is a constraint rather than a preference.** `check-file-hygiene.mjs` lives in buses-data, which is private; this repository is public, so a CI step would need `CROSS_REPO_PAT2` — and hanging a hygiene check off that token is precisely what buses-data's `docs` job was separated out to avoid, since a token expiry must not take the documentation checks down with the byte gates. Moving the checker to `claude-skills`, which is public, is the honest fix and is **not done**. The hook finds it by `git config hooks.busesDataPath`, defaults to where buses-data sits on this machine, and — like the stamper beside it — stays silent rather than blocking when the checker is absent, because a hook that dies on a machine without it teaches whoever hits that to bypass the hook for good.

**And the half of that checker no CI run anywhere could ever perform.** `core.autocrlf=true` is set on this machine, so with `text=auto` the index normalises to LF the moment a file is staged: **a file carrying CRLF at the top and LF at the bottom produces a perfectly clean diff.** `actions/checkout` then builds a uniform tree, so CI sees nothing either. Mixed line endings are a property of a WORKING TREE, exactly like the untracked-sibling check in buses-data's hook — and the hook is therefore not a weaker copy of a CI step, it is the only place the question can be asked at all. The fault was found because a `pairs` entry in buses-data's `failure-shape-memories.json` would not match its own outer object; that repository's `.gitattributes` turned out to be mixed in the same way, lines 1–21 CRLF and 22–40 LF.

**Watched refusing before it was trusted:** a staged BOM refused, the same commit allowed once the mark was gone, and seventeen falsification cases behind the checker itself — every one of its three exemptions tested in both directions, because widening an exemption produces a false PASS rather than a false finding.
