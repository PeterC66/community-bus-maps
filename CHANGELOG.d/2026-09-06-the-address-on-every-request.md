title: "The visitor's address is masked before it reaches either log, and the access log's retention is a decision rather than a default"
---

buses-data OA-086 phase 1, the gate P8b is actually waiting on. Embedding a map on a council's page makes us a processor for that council's visitors — people who never chose to contact us — so the addresses stop being collected **before** the embed rather than with it.

- **Both logs mask, to the same prefix, and the prefix is asserted across the two files.** `maskIp()` in `src/public/logRedaction.js` takes an IPv4 address down to its /24 and an IPv6 address to its /32; the `Caddyfile`'s access log does the same with `ip_mask`. That is one rule living in two files that never see each other, so `scripts/test-caddyfile.mjs` imports `IP_MASK_BITS` and asserts the Caddyfile's numbers against it — the failure that actually happens to a rule kept in two places is that the half somebody is editing moves and the half they are not stays.
- **Caddy writes the address under TWO names and masking one of them is the obvious way to get this wrong.** Since v2.7 it logs `remote_ip`, the socket's peer, and `client_ip`, the address parsed from the forwarding headers. A line with one masked and the other in full reads almost exactly like a correct one. Both are named in the filter, both are asserted, and `npm run deploy:caddy`'s post-deploy instructions now tell you to check both by eye on the host — a log filter shows up in no response header, so it is not a `curl`.
- **/24 and /32, not the conventional /24 and /48.** Google Analytics zeroes an IPv6's last 80 bits, which is a /48 — and a residential IPv6 allocation is a /56 or a /48, so that mask leaves the household's whole prefix and anonymises nothing. /32 is the honest analogue of the /24: what survives is which provider and roughly where, which is all a /24 leaves of an IPv4 address and all either log needs.
- **The rate limiter still sees the full address, deliberately.** `rateLimited()` buckets in memory for sixty seconds and writes nowhere, so masking at the point of logging and keeping the address at the point of decision are separable — and they were already separate, which is the whole reason this change is small. /24 buckets would let one abusive host spend a street's allowance.
- **The serialiser moved out of `src/server.js` so a test could reach it.** It was a function body inside a Fastify config object, so every assertion in the repository stopped one call short of the object that actually reaches the log: a change that kept both helpers and quietly stopped calling one would have broken nothing any test could see. It is now `loggableReq()` beside the helpers, and `scripts/test-indexing.mjs` calls the same function Fastify does and reads the line back.
- **"Rotated by nothing here" was misread as not rotated at all, including by the commit that fixed it.** Caddy rolls a log file **by default** — 100 MiB, 10 files, **90 days** — so the real state was a 90-day retention nobody had chosen and nothing had written down. The block now states 10 MiB, 10 files and 720h, `/legal.html` tells the public 30 days, and the test holds the file to the number the page promises.
- **`/legal.html` now describes what actually happens.** It said "short-lived server logs including your IP address"; it now says the address is masked before it reaches a log, what survives, that the full address is used only for the moment it takes to rate-limit a form and is never written down, and that logs are kept for 30 days. `scripts/personal-data.mjs` gains the paragraph that follows from it: a subject-access request can be answered from the database alone precisely because no log line can be joined back to a person, and if that ever stops being true it stops being true there first.
- **Eight mutations, each caught by the assertion that names it.** `scripts/prove-red-visitor-ip.mjs` breaks the masker three ways, cuts the wire between the masker and the log, masks only one of Caddy's two fields, adopts the conventional /48, moves `IP_MASK_BITS` while leaving the Caddyfile behind, and drops the retention. Every failure this guards against is silent — nothing 500s, no page breaks, no header changes — so watching each one go red is the only way to know the assertions bite.
