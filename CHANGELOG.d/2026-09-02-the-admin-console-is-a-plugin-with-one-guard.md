date: 2026-09-02
title: "The admin console is a Fastify plugin with one guard, and the route table is now something a test can hold"
---

`src/server.js` held every one of the portal's route registrations — 92 of them, 3,363 lines — and the 2026-09-01 codebase review (portal-src F1 and F8, `buses-data` OA-231, Tier 4.4) named the risk in that shape: the admin console's 22 routes each opened with their own `requireAdmin()` call, and a new admin route that forgot the line was refused by nothing. This is the first cut along the file's own banners, admin first, and nothing a caller can see has changed: the route table is byte-identical before and after, and a test says so.

- **The route table is recorded, and held.** An `onRoute` observer in `server.js` collects every route as it is registered; `scripts/route-table.json` is that list as the UNSPLIT server registered it (148 routes, HEAD twins included), and `scripts/test-admin-plugin.mjs` asserts the live app against it. A route that moves between files is invisible to the check, which is the point; one gained or lost is not. It was green on the unsplit code first — the control the cut is measured against.
- **`src/routes/admin.js` is the admin console, and it has ONE guard.** The 22 handlers moved verbatim (a script that compares every line of the new file against the old `server.js` finds nothing changed but the prefix, the `requireAdmin()` line each used to open with, and the plugin's header). The guard is a plugin-level `preHandler`, so a route registered in that file cannot be added without it. The one exception is declared as route config rather than as a second call site: `GET /worklist` admits the read-only OPERATOR_TOKEN, and the guard reads that flag itself. The same test enumerates every `/api/admin/` route in the live table — not a list written by hand — and asserts the door on each: anonymous 401, editor 403, approver 403, admin reaches the handler, and the refusal is the guard's own sentence rather than the CSRF hook's.
- **What moved out BEFORE the cut, not during it.** `src/http/helpers.js` holds the guards and the small request helpers every route file needs (`str`, `parseJson`, `baseUrl`, `requireUser`/`requireAdmin`/`requireApprover`, `requireStepUp`, `operatorRead` and the constants), and `src/maps/detail.js` holds `mapDetail()` and the load-a-map family the editor, review and monthly-refresh sections share. Both are verbatim moves with computed import lists — a route file imports them instead of closing over a scope it no longer lives in, which is what makes the next cuts mechanical.
- **`POST /api/admin/status` is deliberately not in the plugin.** It is the STATUS_TOKEN drop-box for the operator's laptop and it 404s to a session — the opposite of the guard — so it stays with the other token-authorised ops routes.
- **The falsification harnesses moved with the code.** `prove-red-access-model.mjs` and `prove-red-operator-token.mjs` mutate the files the guards now live in, and the access-model arm that used to swap one route's `requireAdmin` for `requireUser` now opens the plugin's single guard instead — one mutation, 22 routes, caught by the same assertion. `test-operator-token.mjs`'s closed question ("operatorRead is consulted in two places and nowhere else") is now asked of every file under `src/`, which is the stronger form: a third call site in a new route file is exactly what a one-file read would have missed.
- **Not in this PR, and next under the same row:** the review, monthly-refresh and editor sections along the same seams; then one error handler emitting the standard envelope, and one env reader.
