title: "A gate that asks what actually loaded, rather than what the source looks like"
---

`Development Docs/open-actions.md` in `buses-data`, OA-129 Phase 3. Follows the same day's require-scan fix.

- **`npm run test:selfsufficient` renders a real map through this repository's engine and records every module Node actually resolves, then fails if one of them came from outside.** It lays the scratch folder out the way a map's own data pack is — the json inputs plus `gen_internal.js`, no sibling modules, `SKILL_ASSETS` pointing at `engine/` — so it covers the path a newly **imported** map takes. `verify:place` renders from `engine/place/` directly and does not.
- **Why it is not the check we already had.** `requireScan()` answers a similar question by pattern-matching the engine's source for the idiom a resolver is written in, and earlier the same day that heuristic was shown to be one: it had never seen `gen_boarding.js`, which factors its resolver into a `_dep(name)` helper so no module name sits beside `SKILL_ASSETS`, and it went blind to `gen_internal.js` the moment that file was tidied the same way. The patterns are fixed and still worth having — they name the missing file before anything runs, which is a better error than a stack trace — but a pattern over source text only covers the forms somebody thought of. This one observes the load, so a new idiom, a lazy require inside another module, or a path built by arithmetic all show up without anyone extending a regex.
- **The laptop cannot answer this question and CI can**, which is why the step lives in the `verify` workflow. Every generator's last-resort module resolution is a hardcoded path into the skill checkout; that folder exists here, so a module this repository was never given still resolves and the sheet still renders. On the runner it does not exist, and a missing module is `MODULE_NOT_FOUND` — which is what the server would have done.
- **Deliberately NOT in `npm test`.** The test workflow does not check out `buses-data`, so a fixture-dependent script there would fail on every run from the day it landed, which is how a check gets muted rather than fixed. It sits in `npm run verify` alongside the other three reproduce gates, and honours `--allow-skip` the way they do for a clone of the portal on its own.
- **Both assertions were watched go red, separately, because they fail for different reasons.** Removing `engine/poi_select.js` makes the generator throw and the run fail on "runs to completion". Injecting a `require` that reaches straight into the skill tree, bypassing `_dep` entirely — the shape a new idiom would take — leaves the sheet rendering perfectly and fails only on "every module came from `engine/` or the map data pack". A third assertion guards the vacuous case, where the loader shim records nothing at all and the other checks pass over an empty list.
