---
date: 2026-08-31
title: "The edge and the crawler: www 308s to the apex, and the access log stops recording a live credential"
---

Three `buses-data` backlog rows converged on one file. OA-006(a) wanted a `log { }` filter in the `Caddyfile`; OA-172 wanted `www.busmaps.uk` to stop being an alias and start being a redirect; OA-015 is the Search Console submission whose only recorded wart was OA-172. Two of them are a proxy change, so they are one deploy rather than two, and the third is a handover that reads better once the first two are live.

- **`www.busmaps.uk` is now its own site block and 308s to the apex.** (It shipped saying `permanent` and answered **301**; corrected within the hour — see the note at the end.) It was an address on the same block as `busmaps.uk`, which is what made automatic TLS cover both and is correct as far as it goes — but nothing downstream then picked a winner, so the two homepages hashed the same and www served its own `robots.txt` and its own `sitemap.xml`. `permanent` rather than `301`: a 308 preserves the method, and nothing here should quietly turn a POST into a GET. HSTS is set on the name in its own right, because the apex's `includeSubDomains` only reaches www **after** a browser has visited the apex, and the visitor this block exists for arrives at www first.
- **Thirteen pages now say where they really live.** Every `/m/<slug>` page has emitted a canonical for weeks; the hand-written pages emitted none, so each was reachable as two indexable copies with nothing to say which was authoritative. The redirect collapses that at the edge for every path at once, including ones nobody has written yet, which is why it is the primary fix — the canonicals are what a page **copied from another page** inherits, which a proxy rule is not. The three server-filled shells (`map.html`, `services.html`, `org.html`) are deliberately left without one: two canonicals in a document is worse than none.
- **The access log redacts `q` and `token` by name, on BOTH blocks.** `src/server.js` has stripped `q` off the search routes since P9 B8, on the rule that "search queries are never logged, and an access log counts as a log", and its own comment named this as the follow-on it could not reach. Importing the log into the www block too is not tidiness: a redirect preserves the query string, so `www.busmaps.uk/maps?q=…` writes the term on its way past, and redacting one block would have looked completely fixed from the apex. `replace` rather than `delete`, so the log still shows *that* a search happened; `wrap json` written down rather than inherited, so a later `format` edit cannot silently change the format of a file something may one day parse.
- **`token` is in that list because of what was found while writing it.** `/auth/verify?token=…` is a magic link — the one credential on this site that **cannot** be moved into a header, because it arrives as a link in an email. It is single-use with a 15-minute TTL, and a cross-site arrival only *peeks* at it and shows a confirmation page, so the token in a log line can still be spendable when somebody reads it. Both logs recorded it in full. The two **ops** tokens that used to accept `?token=` were deleted outright in the 2026-08-25 audit (N7) precisely because they could be; this one is stripped from the application log (`src/public/logRedaction.js`) and redacted at the edge instead. **The two lists are separate and must be kept together**: Fastify's is by route prefix because it knows the route, Caddy's is by parameter name because a proxy does not.
- **`/background.html` was linked from every page and in no sitemap, four hours after it shipped.** Portal #176 added it at 14:03 and put it in the footer of all sixteen pages. The comment above `STATIC_PAGES` has said since P6 that "every public page that is linked from the footer" is in that list, and gave the reason — *excluding it would hide it from crawlers while showing it to every visitor, which is not privacy, just inconsistency*. The rule was true when written, enforced by nothing, and false by the end of the same day. `STATIC_PAGES` is now `src/public/staticPages.js` and `scripts/test-indexing.mjs` joins it to `FOOTER_HTML` **in both directions**, plus to the directory listing, so a page added without being listed is a finding rather than a silent omission. The sitemap goes from 47 URLs to 48.
- **The deploy script was about to be wrong about its own hostname.** `deploy-caddy.mjs` found the public hostname with "the first non-comment line ending in `{`", which was true while the file held exactly one site block — and a `(access_log)` snippet definition is that shape exactly. It would have verified `https://(access_log)/`. Nothing reasoned its way to that; it was found by asking what reads the file *before* editing the file. The parse is now `scripts/lib/caddyfile.mjs`, and `scripts/test-caddyfile.mjs` drives the **old** one-liner at the **current** file and asserts it gets it wrong, because a guard that has never been seen to fail proves nothing.
- **`npm run deploy:caddy` now reads the redirect back, and says plainly what it cannot read back.** It asserts `https://www.busmaps.uk/` answers `308` with the apex, alongside the header set. The log filter shows up in no response header, so instead of implying it checked, the script prints the two commands that read it on the host. **Merging this changes nothing** — the `Caddyfile` ships through `npm run deploy:caddy` and through nothing else, which is exactly how the security headers came to be merged, deployed and still absent from the live site on 2026-08-20.

**Correction, the same day, caught by the deploy's own read-back.** The block first went out as `redir … permanent`, and this entry, the `Caddyfile` comment beside it and `scripts/test-caddyfile.mjs` all said that meant a 308. **Caddy's `permanent` is a 301.** The live site answered `NO  301 https://busmaps.uk/` against an assertion written for 308, and that read-back is the only thing in the loop that could have said so — Caddy is installed neither on this laptop nor on the CI runner, so no test here could ever have contradicted the comment. The directive now names the number, `redir https://busmaps.uk{uri} 308`; the test asserts the literal directive **and** refuses the words `permanent`/`temporary` on a `redir` line, and both arms were watched go red on the reverted file. Nothing about the canonical half turned on it — for search engines 301 and 308 are equivalent — and the reason to keep 308 is method preservation on a catch-all block for paths nobody has written yet. **The lesson is the smaller one:** a comment asserting the behaviour of a tool that cannot be run in the repository is an untested claim set in the same font as the tested ones.
